# 通用

## 时钟（RCC）

> **一句话版**：STM32 里每个外设都有一道「电闸」，默认是**关着**的。不开闸，你写寄存器等于写空气。

### 为什么要有它

STM32 内部有几十个外设（GPIO、USART、TIM、ADC…）。如果**全部一直通电**，功耗会非常高。
所以厂商给**每个外设单独做了一道开关**（时钟门控），**默认全部关闭**。

### 为什么这很重要

```c
RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);   /* ★ 不开这行，下面全部无效 */
GPIO_Init(GPIOA, &GPIO_InitStructure);                   /* 看着执行了，其实没生效 */
```

**最经典的现象**：代码完全正确、能编译、能下载，但**板子一点反应都没有**。
—— 99% 是**忘了开时钟**。而且**不会报错**，因为写一个关闭的外设寄存器，硬件就是**默默忽略**。

### 有三条总线，别记混

| 总线 | 频率（F103 @72MHz） | 挂在上面的外设 |
|---|---|---|
| **AHB** | 72 MHz | DMA、SRAM、Flash 接口 |
| **APB2** | **72 MHz**（高速） | **GPIOA~E**、**USART1**、**SPI1**、**TIM1**、**ADC1**、AFIO |
| **APB1** | **36 MHz**（低速） | **USART2/3**、**TIM2~TIM4**、**I2C**、SPI2、CAN |

> ⚠️ **这个差异直接决定波特率**：`USART1` 在 APB2（72MHz），`USART2/3` 在 APB1（36MHz）。
> **同一个 115200，两个外设算出的 `BRR` 不一样。** 代码照抄不改总线 → **串口全乱码**。

### 面试常问

- 「为什么串口初始化要开**两个**外设时钟？」→ **GPIOA（引脚在 GPIOA）+ USART1（外设本身）**，是两个独立外设。
- 「开了 AFIO 时钟有必要吗？」→ **UART 复用不需要**，只有**引脚重映射**或 **EXTI 外部中断**才要。

## GPIO

> **一句话版**：**引脚的方向盘和挡位**。决定这个脚是「听」还是「说」、用哪种电气方式说。

### 八种模式，先记四类

| 类别 | 模式 | 什么时候用 |
|---|---|---|
| **输出** | `Out_PP`（推挽） | LED、继电器、**方向控制脚** |
| | `Out_OD`（开漏） | I2C 总线（**必须开漏**，允许多设备线与） |
| **复用输出** | `AF_PP` | ★ **交给外设驱动**：**UART TX**、PWM 输出 |
| | `AF_OD` | 外设驱动 + 开漏（如 I2C 的复用） |
| **输入** | `IPU`（上拉） | **UART RX**、按键（按键接地时用上拉） |
| | `IPD`（下拉） | 按键（按键接 VCC 时用下拉） |
| | `IN_FLOATING`（浮空） | 外部已有上下拉时 |
| **模拟** | `AIN` | **ADC 采集**（此时引脚的数字功能关闭） |

### ★「普通输出」和「复用输出」的区别 —— 面试高频

| 模式 | 谁在控制引脚电平 |
|---|---|
| `Out_PP` | **ODR 寄存器**（你写 `GPIO_SetBits` 就变高） |
| `AF_PP` | **片上外设**（USART / 定时器） |

**所以**：
- **UART 的 TX 必须是 `AF_PP`** —— 因为要由 USART 外设决定什么时候发高低电平。写成 `Out_PP` → **串口一个字节都发不出去**。
- **PWM 输出也必须是 `AF_PP`** —— 由定时器决定。

### 面试常问

- 「推挽和开漏的区别？」→ 推挽能**主动输出高和低**；开漏**只能拉低**，高电平要靠外部上拉。I2C 用开漏是为了**多设备共享一条线不会短路**。
- 「按键为什么要上拉/下拉？」→ 按键没按时引脚**悬空**，电平不确定，会**乱读**。上拉/下拉给它一个**确定的默认电平**。

## 外设

> **一句话版**：**芯片里专门干某件事的硬件模块**。CPU 只要「配置 + 读结果」，中间过程硬件自己跑。

| 外设 | 专职干什么 |
|---|---|
| **GPIO** | 管引脚电平 |
| **USART** | 串口收发电平（一位一位地移） |
| **TIM（定时器）** | 数数。衍生出：定时中断 / **PWM 输出** / **编码器接口** / 输入捕获 |
| **DMA** | 内存 ↔ 外设**搬数据**，不问 CPU |
| **I2C / SPI** | 和传感器/屏幕通话 |
| **ADC** | 把电压变成数字 |
| **CAN** | 抗干扰的差分总线（进阶拓展用） |

> 🎯 **贯穿全项目的核心思想**：
> **凡是「高频、精确、长时间重复、CPU 不该参与」的活，都交给外设。**
> **凡是代码里有「CPU 在死等」的地方，都该问一句：有没有外设能替我干？**
> 这一问，就是嵌入式工程师和「会写 C 的人」的分界线。

## 寄存器

> **一句话版**：**芯片内部一个个 32 位的小格子**。你往里面写数字，硬件就按这个数字干活。

- **标准外设库（SPL）** 是把「往格子写数字」包装成了 `XXX_Init()` 函数，**让你不用查手册算位**。
- **HAL 库 / LL 库** 是 ST 后来推的，抽象层次更高，但**代码更臃肿、更慢**。
- **本项目用 SPL**（江科大风格），原因：**结构直观、贴近硬件、教学价值高**。

**面试常问**：「你用寄存器还是库？」→ 好答案：**「库为主，但知道自己写的每一位落在哪个寄存器上」** —— 因为出问题时要看寄存器。

## 轮询 vs 中断

> **一句话版**：**轮询 = 你一直盯着问「好了没」；中断 = 好了它叫你。**

| | 轮询（Polling） | 中断（Interrupt） |
|---|---|---|
| 做法 | `while(标志位==0);` 死等 | 配置好，事件来了自动跳进函数 |
| 优点 | 简单、可控、无并发问题 | **CPU 不用等**，可同时处理多件事 |
| 缺点 | ★ **CPU 被浪费**，且**没法同时等两件事** | **有并发风险**：中断和主循环会「抢」同一个变量 |
| 用在哪 | 只在**确定很短**的等待 | **一切「不知道什么时候来」的事件** |

### ★ 中断的三个必知概念

| 概念 | 含义 |
|---|---|
| **中断服务函数（ISR）** | 事件发生时自动执行的函数，如 `USART1_IRQHandler` |
| **NVIC** | 内核里的**中断管理器**，管优先级和开关 |
| **优先级** | 决定「多个中断同时来，先执行谁」，以及「能不能打断正在执行的中断」 |

**开一个中断要开两层（★ 必背）：**

```c
USART_ITConfig(USART1, USART_IT_RXNE, ENABLE);   /* 第一层：外设级 */
NVIC_Init(&NVIC_InitStructure);                  /* 第二层：内核级 */
```

**少任何一层，中断函数都不会被调用。**

### ★ 中断里的三条铁律

1. **短**：中断里不能有耗时操作（长循环、`Delay`、**I2C 读传感器**）。
2. **纯**：只做「不需要等待」的事。
3. **不碰共享资源**，或者**必须保护**。

> **本项目真实踩过的坑（八阶段）**：
> 把「读 MPU6050（软件 I2C，耗时 5ms）」放进 10ms 中断 →
> ① 占满 70% 时间 ② **和主循环里的 OLED 抢同一条 I2C 总线 → OLED 花屏、姿态读数错乱、极难复现**。
> → 解决：**拆成 `Attitude_Sample()`（主循环做 I2C）+ `Attitude_FilterUpdate()`（中断做数学）**。
>
> 🎯 **面对共享资源只有两种正确做法：① 加互斥（复杂、易死锁）② 消除并发（简单、无锁）。**
> **能靠「消除并发」解决的，就不要靠「加锁」解决。**

# 一阶段：双机通信

## 串口（UART / USART）

> **一句话版**：**最古老也最常用的通信方式**——一根线发、一根线收，一位一位地传。

| 名字 | 含义 |
|---|---|
| **UART** | 通用异步收发器（**只有异步**） |
| **USART** | 通用**同步/异步**收发器（**多了同步功能**） |
| **TTL 串口** | 电平 0V/3.3V（单片机用的） |
| **RS-232** | 电平 ±12V（老电脑用的，**接错会烧芯片**） |
| **RS-485** | 差分信号，抗干扰强、传得远（工业用） |

**接线只要三根：TX、RX、GND。**

```text
A 的 TX ──► B 的 RX
A 的 RX ◄── B 的 TX
A 的 GND ── B 的 GND      ← ★ 最容易漏，漏了必不通
```

> **为什么叫「交叉」**：A 的「嘴」要对着 B 的「耳朵」。TX 接 TX 就是两张嘴对喊，谁也听不见。

---

## 波特率

> **一句话版**：**每秒传多少个「位」**。115200 就是每秒 11.52 万个二进制位。

### 为什么需要它

串口是**异步**的——**没有时钟线**告诉接收方「现在该采样了」。
所以双方必须**事先约定同一个速度**，接收方靠**计时**来判断每一位的位置。

### 怎么算（★ 面试必会）

```
一位的时间 = 1 / 波特率
115200 → 1 / 115200 ≈ 8.68 µs
9600   → 1 / 9600   ≈ 104 µs
```

**一个字节（8N1）实际占 10 位：**

```text
[起始位 1位][数据 8位][停止位 1位] = 10 位
115200 下发 1 个字节 = 10 × 8.68µs ≈ 86.8 µs
9600   下发 1 个字节 = 10 × 104µs ≈ 1.04 ms
```

> ⚠️ **这个数字很有用**：交接文档里算「整帧 10 字节 @9600 = 10.4ms，占 20ms 心跳的 52%」
> —— **就是这么算出来的**。**带宽核算是嵌入式设计的基本功**，面试很爱问。

### 常见值

| 波特率 | 一位时长 | 典型用途 |
|---|---|---|
| **9600** | 104 µs | **HC-05 蓝牙默认**、要求不高的场合 |
| 115200 | 8.68 µs | ★ **最常用**：电脑串口、VOFA+ |
| 921600 | 1.09 µs | 高速数据（波形、图像） |

### ★ 为什么波特率必须一致，误差容限只有 2~3%

接收方在**起始位的下降沿**对齐，然后每隔「一位时间」采一次样。
如果双方速度差得多，**误差会累积**：采到第 8 位时可能已经偏了半个位宽 → **采错**。

**这就是为什么「波特率对但晶振频率假设错」也会乱码**：
板子焊的是 8MHz 晶振，代码按 12MHz 算 → 实际波特率整体偏移 → **照样乱**。

### 波特率怎么变成寄存器值

```c
USART_InitStructure.USART_BaudRate = 115200;   /* 库函数帮你算 BRR */
```

内部公式：`BRR = f_PCLK / (16 × 波特率)`

| 例子 | 计算 | BRR |
|---|---|---|
| USART1 @72MHz, 115200 | 72e6/(16×115200) = 39.0625 → 整数 39、小数 0.0625×16=1 | **0x271** |

> **`BRR` 高 12 位是整数分频、低 4 位是小数分频** —— 所以才能做到「不是整数倍也能对上」。

### 面试常问

- 「115200 下 OH 一个字节要多久？」→ **86.8 µs**（记住 8N1 是 10 位）
- 「为什么 9600 下不能每 10ms 发一帧 10 字节？」→ **一帧就要 10.4ms，比周期还长** → 链路饱和

## 异步通信

> **一句话版**：**没有时钟线，靠「事先约定的时间」对齐**。

| | 异步（UART） | 同步（I2C / SPI） |
|---|---|---|
| 时钟线 | ❌ 没有 | ✅ 有（SCL / SCK） |
| 怎么对齐 | 靠**起始位** + **约定的波特率** | 靠**时钟线**，收方跟着时钟走 |
| 线数 | 2 根（TX/RX） | I2C 2 根、SPI 4 根 |
| 抗干扰 | 一般（速度不能太高） | 好 |

**「异步」的代价**：每传一个字节，都要额外送**起始位 + 停止位**（2 位开销），
而且**双方时钟必须够准**。**好处是省线**。

## 帧头帧尾

> **一句话版**：数据流是一串没有边界的字节，**帧头帧尾就是给数据「加上括号」**。

### 为什么需要

```text
串口上实际流过的：A5 02 00 3C 3E 0D A5 02 00 3C 3E 0D A5 02 ...
                  └──── 第一帧 ────┘ └──── 第二帧 ────┘
```

接收方**怎么知道哪里是一帧的开始、哪里是结束？**
→ **约定一个特殊字节做开始（帧头 `0xA5`）、一个做结束（帧尾 `0x0D`）。**

**PDF 硬性要求 3 就是这条**：「通信协议必须包含帧头 `0xA5`、帧尾 `0x0D`」。

### 本项目协议

```text
[0xA5][len][data...][checksum][0x0D]
  帧头   长度   数据     校验和    帧尾
```

| 字段 | 作用 |
|---|---|
| `0xA5` | 帧头：告诉接收方「新的一帧开始了」 |
| `len` | ★ **长度：本帧数据区有多少字节**（**长度驱动解析的关键**） |
| `data` | 真正要传的内容 |
| `checksum` | 校验和，检查传输有没有出错 |
| `0x0D` | 帧尾：本帧结束 |

> 🎯 **为什么不把「数据长度」写死在代码里？**
> 因为**数据内容会变**（八阶段从 3 字节扩到 5 字节）。
> **把长度写进帧里** → 接收方**动态知道要读多少** →
> **扩协议时，帧格式、校验规则、解析状态机全部不用改**。这叫「**长度驱动**」。

## 校验

> **一句话版**：**一个用来发现「数据传错了」的冗余字节**。

### 为什么需要

串口线会受电磁干扰，**某个位可能从 0 翻成 1**。
如果不检查，接收方会把**错的数据当对的用** —— 对电机控制来说，这可能意味着**小车突然窜出去**。

### 常见几种

| 方式 | 做法 | 能查出 |
|---|---|---|
| **奇偶校验** | 数 1 的个数是奇还是偶 | 只能查**单个位**出错（UART 硬件自带） |
| **累加和（本项目用）** | 所有字节相加，取低 8 位 | 大部分错误（简单快速） |
| **CRC** | 多项式除法 | ★ **最强的常用校验**（能查多位错、突发错） |
| **MD5 / SHA** | 密码学哈希 | 完整性 + 防篡改（**嵌入式不用，太重**） |

**本项目的校验和**：

```c
/* 校验和 = len + data 各字节，取低 8 位 */
uint8_t sum = len;
for (i = 0; i < len; i++) { sum += data[i]; }
/* 接收端重算一遍，和收到的 checksum 比对，不一样就丢帧 */
```

### 面试常问

- 「累加和和 CRC 的区别？」→ 累加和**便宜但弱**（两个字节互换位置查不出来）；CRC **强但要查表/移位**。
- 「校验失败怎么办？」→ **直接丢帧，不猜、不修**。宁可丢一帧，也不能用错数据。

## 粘包

> **一句话版**：**发送方分几次发，接收方可能一次全收到；或者反过来，一帧被切成两半。**

### 为什么会发生

串口是**字节流**，没有「消息边界」的概念。接收方（尤其用 DMA 时）**读到的是一坨字节**，不是整齐的帧。

```text
发送方发了两帧：
   A5 02 00 3C 3E 0D   A5 02 00 3C 3E 0D

接收方可能一次读到：
   A5 02 00 3C 3E 0D A5 02 00 3C 3E 0D    ← 粘在一起了（粘包）
   或
   A5 02 00 3C         ← 只到一半（半包/拆包）
```

### 怎么解决（★ 面试重点）

**靠状态机逐字节解析，而不是「一次读到一帧」。**

```text
状态机：等帧头 → 读长度 → 收数据 → 校验 → 等帧尾 → 输出一帧 → 回到「等帧头」
```

**核心是**：**收到多少就处理多少，剩下的留在缓冲区等下次**。
- **粘包** → 状态机解析完第一帧后，**继续解析剩下的字节**（不要清空缓冲区）。
- **拆包** → 状态机**保持当前状态**，等下一批数据到来继续。

### ★ 智能重同步（本项目的一个细节）

**「解析失败时怎么恢复」是很能看出水平的地方：**

| 做法 | 评价 |
|---|---|
| 丢整帧、清空缓冲区、从头开始 | ❌ 不好：**如果帧尾恰好是 `0xA5`，会把下一帧的帧头也丢掉** |
| ★ **重新检查当前字节是不是 `0xA5`** | ✅ **好**：如果这个字节是 `0xA5`，它**可能就是下一帧的帧头**，直接开始新帧 |

这叫「**智能重同步**」—— **出错恢复时，不要浪费任何可能是有效数据的字节。**

## DMA

> **一句话版**：**一个专职搬数据的「搬运工」硬件**，CPU 只要告诉它「从哪搬到哪、搬多少」，然后就撒手不管。

### 为什么需要

**没有 DMA 时**，CPU 要一个个字节地处理：

```c
while (1) {
    if (收到一个字节) {
        buffer[i++] = 取走字节;   /* CPU 亲手搬 */
    }
}
```

- 115200 下**每 87µs 一次中断**，几万次/秒，CPU 被切碎。
- 如果是**每字节一次中断**，那更是灾难。

**有了 DMA 后**：

```text
数据从外设 → 自动进内存，CPU 完全不参与
CPU 只在「一帧收完了」时被叫醒一次
```

**CPU 占用从「每字节一次」降到「每帧一次」。**

### 关键的几个寄存器

| 概念 | 含义 |
|---|---|
| **通道（Channel）** | F103 的 DMA1 有 **7 个通道**，每个挂一个外设请求。**USART1_RX 固定用 DMA1_Channel5** |
| **源/目标地址** | 从哪搬到哪（外设数据寄存器 ↔ 内存数组） |
| **传输数量** | 要搬多少字节 |
| **`DMA_GetCurrDataCounter()`** | ★ **还剩多少没搬**（递减）。**用它反推「已经收了多少」** |
| **循环模式** | 搬完自动重头开始（接收时常用） |

### 面试常问

- 「DMA 有什么用？」→ **解放 CPU、提高吞吐、避免丢数据**。
- 「DMA 收数据怎么知道收完了？」→ ☆ **看下面的「空闲中断」**。

---

## 空闲中断（IDLE）

> **一句话版**：**「总线安静下来了」这个事件，本身就是一个信号** —— 说明一帧收完了。

### 为什么需要

用 DMA 收数据，DMA 只会**默默地搬**，它**不告诉你「这一帧结束了」**。

**那怎么知道一帧收完了？**

| 做法 | 问题 |
|---|---|
| 靠「缓冲区满了」 | ❌ 数据比缓冲区短的话，永远不满 → **永远不处理** |
| 靠「字节间隔超时」 | ❌ 要额外的定时器 |
| ★ **空闲中断（IDLE）** | ✅ **硬件自带**：总线连续一个字节时间没有新数据 → 触发 IDLE 中断 |

**它的精妙之处**：UART 协议规定空闲态是高电平。所以「**一段时间没有起始位**」= **线路空闲** = **发送方说完了**。

### 怎么用（★ 一阶段任务 4 的核心）

```c
/* 初始化时 */
USART_ITConfig(USART1, USART_IT_IDLE, ENABLE);   /* ★ 开 IDLE 中断 */
DMA_Cmd(DMA1_Channel5, ENABLE);

/* 中断里 */
void USART1_IRQHandler(void)
{
    if (USART_GetITStatus(USART1, USART_IT_IDLE) == SET)
    {
        /* ★ 清 IDLE 标志的特殊方式：先读 SR，再读 DR */
        volatile uint32_t tmp;
        tmp = USART1->SR;
        tmp = USART1->DR;
        (void)tmp;

        /* ★ 算出这一帧的长度：总数 − 剩余数 */
        rx_len = BUF_SIZE - DMA_GetCurrDataCounter(DMA1_Channel5);

        /* 处理这一帧...然后重置 DMA 准备下一帧 */
        DMA_SetCurrDataCounter(DMA1_Channel5, BUF_SIZE);
    }
}
```

> ⚠️ **两个坑**：
> 1. **IDLE 标志的清除方式特殊**：必须**先读 SR 再读 DR**，不能像普通标志那样只写 0。
> 2. **`DMA_GetCurrDataCounter` 是递减的** —— **剩余值越小说明收到的越多**，别理解反了。

### 面试常问

- 「DMA + 空闲中断 和 RXNE 中断的区别？」→ **RXNE 每字节一次中断；DMA+IDLE 每帧一次中断**。数据量大时后者完胜。
- 「为什么 IDLE 能判断帧结束？」→ 因为 UART 空闲态是高电平，**没有起始位就说明对方发完了**。

# 二阶段：电机驱动

## PWM

> **一句话版**：**用「快速地开开关关」，模拟出「一半的电压」**。

### 为什么需要

**电机转速 ≈ 加在它两端的平均电压。**
但单片机的 GPIO **只能输出 0V 或 3.3V**，不能输出「1.65V」这种中间值。

**怎么办？** —— **开关得足够快，电机的机械惯性会「平均」掉它**：

```text
100% 占空比：████████████████   → 全速
 50% 占空比：████    ████    ██ → 半速
 25% 占空比：██      ██      ██ → 低速
```

> ★ **PWM 的本质是「用时间的比例，换电压的大小」。**

### 为什么电机「感觉不到」开关

因为**电机的机械时间常数**比 PWM 周期大得多。
20kHz 的 PWM 周期是 50µs，而电机转子不可能在 50µs 内响应 → **它只感受到平均效果**。

**同理**：LED 用 PWM 调亮度，**人眼有视觉暂留**，看不到闪烁（频率够高时）。

### 面试常问

- 「PWM 频率怎么选？」→ **高于人耳（>20kHz）避免啸叫，低于驱动芯片极限**。
- 「PWM 能直接驱动电机吗？」→ ❌ **不能**。GPIO 只有几毫安，电机要几百毫安到几安 → **必须经过驱动芯片（H 桥）**。

---

## 占空比

> **一句话版**：**一个周期里，「开」占了多大比例**。

```
占空比 = 高电平时间 / 周期 × 100%

     ┌────┐          ┌────┐
     │    │          │    │
─────┘    └──────────┘    └─────
     ├────┤
     高电平
     ├───────────────┤
          一个周期
```

| 占空比 | 电机 | LED |
|---|---|---|
| 0% | 不转 | 灭 |
| 50% | 半速 | 半亮 |
| 100% | 全速 | 最亮 |

> ⚠️ **占空比 ≠ 转速，只是近似成正比**。真正的关系还要看**负载**（见 [开环 vs 闭环](#开环-vs-闭环)）。

---

## ARR（自动重装值）

> **一句话版**：**计数器「数到几就归零」**。它决定了 **PWM 频率**。

```text
CNT: 0 1 2 3 ... 98 99 → 0 1 2 3 ... 98 99 → 0 ...
                      ↑ 到 ARR=99 就归零
```

**一个周期 = `ARR + 1` 个数**（★ 因为从 0 数到 99 是 **100** 个数，不是 99 个）。

```
PWM 频率 = 计数时钟 / (ARR + 1)
```

| ARR | 一个周期几个数 | 分辨率 |
|---|---|---|
| **99** | 100 | **1%**（粗，但 CCR 可直接当百分数用） |
| 999 | 1000 | 0.1%（细，适合 PID 输出） |

> **本项目选 `ARR=99`**：因为 `ARR+1 = 100` 正好是百分制分母，
> **`Motor_SetSpeed(50)` 传的 50 既是档位又是 CCR，不用换算**。**这是故意选的数。**

---

## PSC（预分频）

> **一句话版**：**把定时器时钟「降速」的分频器**。它和 ARR 一起决定 PWM 频率。

**关键：分频系数 = `PSC + 1`**（又是「+1」，别记错）。

```
计数时钟 = 定时器时钟 / (PSC + 1)
```

**本项目算例（★ 面试要能现场算）：**

```text
目标：20kHz PWM，定时器时钟 72MHz

取 PSC = 35  →  计数时钟 = 72MHz / (35+1) = 2MHz
ARR = 2MHz / 20kHz − 1 = 100 − 1 = 99

验证：2MHz / (99+1) = 20kHz ✓
```

> 🎯 **两个「+1」是这里的全部难点**：
> **分频系数是 `PSC+1`，一个周期的数是 `ARR+1`。**
> 记住这两条，PWM 频率就永远算不错。

---

## CCR（比较值）

> **一句话版**：**计数器数到几的时候，输出翻转** —— 它决定**占空比**。

```text
CNT < CCR  → 输出高电平
CNT ≥ CCR  → 输出低电平
```

```text
ARR = 99, CCR = 25

CNT: 0 ... 25 ... 99
     ████████░░░░░░░░░░░░   ← 高电平占 1/4
```

```
占空比 = (CCR + 1) / (ARR + 1)
```

> ⚠️ **那个「+1」的细节**：`ARR=99`、`CCR=50` 严格算是 **51%** 不是 50%。
> 只有 `CCR = ARR = 99` 才是真正的 100%。
> **这点误差在电机调速里完全无所谓，但在精确定时里是致命的** —— 敢说这句说明不是背的。

**改占空比 = 改 CCR**：

```c
TIM_SetCompare3(TIM2, 50);   /* CH3 的 CCR 设为 50 → 51% 占空比 */
```

## H 桥

> **一句话版**：**四个开关组成的「电流换向器」**，让电机能正转也能反转。

```text
        +12V
     ┌────┴────┐
    [Q1]      [Q3]
     ├─── M ───┤        M = 电机
    [Q2]      [Q4]
     └────┬────┘
        GND
```

| Q1 | Q2 | Q3 | Q4 | 结果 |
|:--:|:--:|:--:|:--:|---|
| 通 | 断 | 断 | 通 | **正转** |
| 断 | 通 | 通 | 断 | **反转** |
| 断 | 通 | 断 | 通 | **刹车**（绕组短路） |
| 断 | 断 | 断 | 断 | **滑行**（悬空） |
| 通 | 断 | 通 | 断 | 💀 **直通短路！烧管子！** |

### ★ 两个必背的点

**① `0,0` = 滑行、`1,1` = 刹车**（对应 TB6612 的 AIN1/AIN2）

| AIN1 | AIN2 | 结果 |
|:--:|:--:|---|
| 1 | 0 | 正转 |
| 0 | 1 | 反转 |
| **0** | **0** | **滑行（自由停止）** |
| **1** | **1** | **刹车（快速停住）** |

> 本项目第二阶段「**关控模式：电机自由停止**」= **PWM 0 + `0,0` 滑行**，**不是 `1,1`**。

**② 直通（Shoot-through）为什么危险**

`Q1 + Q3` 同时导通 → **+12V 直接回 GND，中间没有电机** → **电流几十安培** → **烧管子**。

**真实芯片里更隐蔽**：开关管**关断有延迟（t_off > t_on）**，
切换瞬间一个管子还没关完另一个就开了 → **每个 PWM 周期都短路一次**。

> ★ **这就是「死区时间（Dead Time）」存在的理由** —— 高级定时器（TIM1）专门插一段「两边都关」的间隙防直通。

### ★ 实际最容易犯的错：换向时没先清零 PWM

```c
AIN1=1, AIN2=0（正转 80%）→ 突然改成 AIN1=0, AIN2=1
中间会经过 0,0 或 1,1 的瞬间 → 负载还在高速转，方向已经反了
→ 电流冲击接近堵转电流 → 长期烧驱动
```

**正确做法：换向前先把 `CCR` 清 0，改完方向再给 `CCR`。**

## 编码器

> **一句话版**：**装在电机轴上的「计数器」**，能告诉你**转了多少、往哪转、多快**。

### 为什么需要它

**开环控制**（只给 PWM、不管实际转速）的问题：**负载一变，转速就变**。
比如小车爬坡时，同样 50% PWM，**转速会掉下来**。
→ **要闭环控制，就必须先「看见」实际转速** → **需要编码器**。

### 常见类型

| 类型 | 原理 | 特点 |
|---|---|---|
| **光电编码器** | 码盘遮光/透光 → 脉冲 | 精度高 |
| **磁编码器** | 霍尔元件 + 磁环 | 抗污染、便宜（**JGB37-520 用的就是这种**） |
| **绝对式编码器** | 每个位置有唯一编码 | 上电就知道位置（贵） |
| **增量式编码器** | 输出 A/B 两相脉冲 | ★ **最常用**：便宜、简单 |

---

## 正交编码器与四倍频

> **一句话版**：**A/B 两路方波相位差 90°**，能同时给出**数量**（转多少）和**方向**（往哪转）。

```text
正转：A ─┐  ┌──┐  ┌──
         └──┘  └──┘
      B ────┐  ┌──┐  ┌
           └──┘  └──┘
      （B 落后 A 90°）

反转：B 超前 A
```

| 你数的东西 | 得到的信息 |
|---|---|
| **脉冲的数量** | **转了多少**（位置） |
| **谁超前谁** | **往哪转**（方向） |
| **单位时间的脉冲数** | **转多快**（速度） |

### ★ 四倍频

**一圈 A、B 各给 N 个脉冲**，但 A、B 组合有 **4 种状态**：`00 → 01 → 11 → 10 → 00`
硬件对**每个状态跳变都计数** → **一圈数到 `4N` 个** → **分辨率 ×4**。

**本项目**：`PPR = 13`、减速比 `30`
```
输出轴一圈总计数 = 4 × 13 × 30 = 1560
```

> ★ **验证方法（最朴素也最可靠）**：**用手把输出轴正好转一圈，看 OLED 上的累计计数是不是 1560。**

### ★ 用硬件，不要用中断数脉冲

```c
TIM_EncoderInterfaceConfig(TIM3, TIM_EncoderMode_TI12, ...);
```

**这一句之后**：
- `CNT` **就是位置**，不需要任何中断
- **方向由硬件判断**
- **CPU 占用为零**

### ⚠️ 三个经典坑

**① `CNT` 回绕**：16 位最大 65535。靠累计值裸算，在 65535→0 时增量变成 **−65535 的巨坑** → **PID 发疯**。
→ 解决：**每周期读完就 `TIM_SetCounter(0)`**。

**② 同号性（★ 最危险）**：底盘两侧电机**镜像安装**，右轮 A/B 极易接反 →
**给正 PWM 时右轮读数为负** → **PID 变正反馈 → 一上电小车冲出去**。
→ 必做：给小正 PWM，看两轮读数**是否都为正**。

**③ 测速方法的取舍：**

| 方法 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **M 法（测频率）** | 固定时间 T 内数脉冲 | 高速精度高 | **低速时分辨率极差** |
| **T 法（测周期）** | 数一个脉冲间隔用了多少时钟 | **低速精度高** | 高速时计时器分辨率不够 |
| **M/T 法** | 两者结合 | 全速域都好 | 实现复杂 |

> 本项目用 **M 法 + 10ms 定周期**。**10ms 是刻意选的**：
> 太短 → 低速读数**跳**；太长 → PID **反馈延迟大**。

## 开环 vs 闭环

> **一句话版**：**开环 = 蒙着眼睛开车；闭环 = 看着仪表开车。**

```text
开环：目标 → [驱动] → 电机转        （不看结果，错了也不知道）
闭环：目标 → [比较] → [驱动] → 电机转
              ↑                    │
              └──── 编码器反馈 ◄────┘
```

| | 开环 | 闭环 |
|---|---|---|
| 反馈 | 无 | **有（编码器/传感器）** |
| 负载变化 | ❌ **转速跟着变** | ✅ **自动补偿** |
| 电池电压下降 | ❌ 转速下降 | ✅ 自动补偿 |
| 实现难度 | 简单 | 需要反馈 + 控制器（PID） |

**PDF 硬性要求 5 就是这条**：「实现速度 PID 闭环」——
**注意 PDF 要求的是「闭环」，不是「能转」。**

# 四阶段：蓝牙无线

## 蓝牙 HC-05

> **一句话版**：**一个把「串口」变成「无线」的模块**。对 STM32 来说，它就是一个「可以隔空连的串口线」。

### ★ 最关键的一句话

**STM32 完全不知道中间是蓝牙。** 它只知道「我往串口写了个字节」。

```text
STM32 ──串口线(TX/RX/GND)──► HC-05 ~~~2.4GHz 无线~~~► HC-05 ──串口线──► STM32
```

→ **这就是为什么第四阶段「换蓝牙，协议层代码一行都不用改」。**

### 引脚

| 引脚 | 作用 |
|---|---|
| **VCC** | 供电（模块板一般 3.6~6V；**裸模块必须 3.3V**） |
| **GND** | 地 ★ **两端必须共地** |
| **TXD** | 模块**发** → 接 STM32 的 **RX** |
| **RXD** | 模块**收** ← 接 STM32 的 **TX** ⚠️ **不是 5V 耐压，注意电平** |
| **KEY / EN** | ★ **进 AT 模式用**（高电平） |
| **STATE** | 连接状态输出 |

### ★★ LED 闪烁模式 = 最有用的诊断信号

| LED 表现 | 含义 |
|---|---|
| **快闪**（约 1 秒 2 次） | **未连接**，正在等待/搜索 |
| **慢闪**（约 2 秒 1 次） | **AT 命令模式** |
| **双闪后停顿**（2 秒闪两下） | ★ **已连接**，可以传数据 |

> **排查第一步永远是：看 LED。**
> 一直快闪 → **根本没连上，问题在蓝牙配置，跟 STM32 代码一点关系都没有**。

---

## AT 指令

> **一句话版**：**给蓝牙模块发的「配置命令」**，用来改它的名字、波特率、主从角色。

### ★ 进 AT 模式（最容易失败的一步）

| 模式 | 怎么进 | ★ 波特率 |
|---|---|---|
| **数据模式（透传）** | KEY 悬空/低电平，正常上电 | **通常 9600** |
| **AT 命令模式** | **按住 KEY 再接 VCC** | ★ **多数固件固定 38400** |

> ⚠️ **两个必踩的坑**：
> 1. **AT 模式的波特率 ≠ 数据模式的波特率**。用 9600 连 AT 模式 → **发 `AT` 没反应**。
> 2. **必须按住 KEY 再上电**。直接上电是数据模式。

### 常用指令

```text
AT                  测试，返回 OK
AT+ROLE?            查询角色
AT+ROLE=0           设为从机
AT+ROLE=1           设为主机
AT+UART=9600,0,0    设数据模式波特率 9600-8-N-1
AT+NAME=HandBand    设名称
AT+PSWD=1234        设配对密码
AT+CMODE=1          可连任意地址（省事）
AT+ADDR?            查本机地址
AT+BIND=98d3,31,403a2c   绑定目标地址（★ 冒号要换逗号）
```

## 透传

> **一句话版**：**模块只是「转发管道」，不改、不看、不解析你发的内容**。

**好处**：代码里 `Serial_SendByte()` 一行都不用改。
**局限**：**没有地址、没有重传、没有确认**。丢帧了它也不知道。
→ **所以「通信稳定」必须靠你自己的协议解决**（帧序号 + 校验 + 超时）。

## 主从模式

> **一句话版**：**蓝牙连接必须有人「主动找」、有人「被动等」。**

| **从机 Slave** | `AT+ROLE=0` | **被动等待**，不主动找人 |

# 五阶段：MPU6050 与姿态解算

## MPU6050

> **一句话版**：**一个小方块，里面装了两个传感器**：一个测「倾斜」、一个测「转动」，各三个轴，所以叫**六轴**。

### 六轴是哪六个

```text
        Z（垂直，指向上）
        │
        │
        └──────── X
       /
      Y
```

**加速度计 3 轴（X/Y/Z）+ 陀螺仪 3 轴（X/Y/Z）= 6 轴。**

> ⚠️ **注意**：MPU6050 **没有磁力计**（所以它**不是** 9 轴 IMU）。
> 这一条非常关键 —— 它正是 [yaw 零飘](#姿态角pitchroll-yaw) 无法根治的根本原因。

### 怎么和 STM32 说话

| 项 | 值 |
|---|---|
| 接口 | **I2C**（见 [I2C](#i2c)） |
| 从机地址 | **0x68**（7 位地址；AD0 接地）/ 0x69（AD0 接 VCC） |
| 写地址 / 读地址 | **0xD0 / 0xD1**（8 位形式的写法） |
| 本项目引脚 | **PB8/PB9**（软件 I2C，**与 OLED 共用一条总线**） |

### 关键寄存器

| 寄存器 | 作用 |
|---|---|
| `0x6B`（PWR_MGMT_1） | ★ **上电默认睡眠**，必须写 0 唤醒！ |
| `0x1C`（ACCEL_CONFIG） | 加速度计量程：±2/4/8/16 g |
| `0x1B`（GYRO_CONFIG） | 陀螺仪量程：±250/500/1000/2000 °/s |
| `0x1A`（CONFIG） | 数字低通滤波（DLPF）带宽 |
| **`0x3B` ~ `0x48`** | ★ **数据寄存器，连续 14 字节 = 全部六轴原始数据** |
| `0x75`（WHO_AM_I） | ★ **应返回 `0x68`** —— **调试时第一件事就读它** |

> 💡 **调试第一件事：读 `WHO_AM_I`**。
> 如果返回的不是 `0x68` → **I2C 根本没通**（接线/地址/上拉问题），
> 后面所有「姿态不对」的怀疑都可以先放下。**这一步能把问题范围砍一半。**

## 加速度计与陀螺仪

> **一句话版**：**加速度计 = 测「哪边朝下」的倾角仪；陀螺仪 = 测「转得多快」的转速计。**

### ① 加速度计（Accelerometer）——「倾斜仪」

**测什么**：**加速度**，单位 **g**（1 g = 9.8 m/s²）。

**★ 核心认知**：**它永远能测到一个 1 g 的「重力分量」**。
静止时这个 1g 完全来自重力，**方向永远指向地心** → **所以能算出「哪边朝下」。**

**静止平放时：**

| 轴 | 读数 | 含义 |
|---|---|---|
| X | 0 g | 水平，没有重力分量 |
| Y | 0 g | 水平，没有重力分量 |
| **Z** | **+1 g** | ★ **完全承受重力** |

**倾斜后重力会「分」到各个轴上** —— 这就是**算角度的全部依据**。

**原始值 → 物理值**（设 ±2g 量程，灵敏度 **16384 LSB/g**）：

```c
ax_g = (float)raw_ax / 16384.0f;
```

### ★ 由加速度计算角度（Pitch / Roll）

这是**唯一能「绝对」测倾角**的办法：

```c
/* 从原始值算出 g 单位 */
float ax = raw_ax / 16384.0f;
float ay = raw_ay / 16384.0f;
float az = raw_az / 16384.0f;

/* ★ 核心公式：用 atan2 而不是 asin */
pitch = atan2f(-ax, sqrtf(ay * ay + az * az)) * 57.29578f;   /* → 度 */
roll  = atan2f( ay, az)                        * 57.29578f;
```

**为什么用 `atan2` 而不是 `asin`？**

| 方法 | 问题 |
|---|---|
| `asin(ax/1g)` | ❌ **只在 ±90° 内有效**，且**过载时参数超出 [−1,1] 会返回 NaN** |
| ★ `atan2` | ✅ **全 360° 有效**，且**天生抗过载**（分子分母都是加速度，同时放大缩小不影响比值） |

> 🎯 **面试加分点**：能说出「用 `atan2` 是因为全象限 + 抗过载」，说明真写过。

### ② 陀螺仪（Gyroscope）——「转速计」

**测什么**：**角速度**（转得多快），单位 **°/s**（度每秒）或 rad/s。

**原始值 → 物理值**（设 ±250°/s 量程，灵敏度 **131 LSB/(°/s)**）：

```c
gx_dps = (float)raw_gx / 131.0f;    /* 单位：°/s */
```

> ★ **注意：陀螺仪给的是「速度」，不是「角度」，也不是「倾斜」。**
> 想得到角度，**必须积分**：`角度 += 角速度 × 时间`。
> —— **而「积分」正是所有问题的源头。**

### ★ ③ 为什么两者缺一不可（本题的核心）

| 维度 | 加速度计 | 陀螺仪 |
|---|---|---|
| **测什么** | 加速度（含重力） | 角速度 |
| **能否直接给角度** | ✅ 能（靠重力方向） | ❌ 不能，**必须积分** |
| **静态表现** | ✅ **准**（重力是绝对参考，不漂） | ❌ **漂**（积分零偏，误差累积） |
| **动态表现** | ❌ **被运动加速度污染**（车一加速，读数就乱） | ✅ **准**（不受平移加速度影响） |
| **噪声** | ❌ **大**（振动敏感，抖得厉害） | ✅ **小**（读数平滑） |
| **长期** | **不漂** | **漂** |

> ### 🎯 两者恰好互补 —— 这就是「互补滤波」名字的由来。
>
> | | 高频（快变） | 低频（慢变/长期） |
> |---|---|---|
> | 陀螺仪 | ✅ **信它** | ❌ 漂 |
> | 加速度计 | ❌ 噪声大 | ✅ **信它** |
>
> **互补滤波 = 高通滤陀螺仪 + 低通滤加速度计，两者相加。**
> **卡尔曼滤波 = 同一件事的「最优加权版」**，用协方差自动算出该信谁多一点。

**只用加速度计会怎样（PDF 明确禁止的做法）？**

| 场景 | 现象 |
|---|---|
| 手静止 | 角度大致正确，但**抖得厉害**（噪声） |
| **手腕快速翻转** | ❌ **角度完全错乱** —— 此时加速度计测到的**主要是手腕的加速度，不是重力** |
| 小车端电机转动 | 振动让读数抖成一团 |

**只用陀螺仪会怎样？**

| 场景 | 现象 |
|---|---|
| 短时间 | 非常平滑、响应快 |
| **几秒~几十秒后** | ❌ **角度单向跑偏，永不回头**（零偏积分） |

> 💡 **通俗记法**：
> **加速度计像「指南针看方向」——长期可靠，但一摇晃就晃花；**
> **陀螺仪像「看转速表推算走了多远」——短期精准，但时间一长误差就累积。**

## 姿态角（Pitch / Roll / Yaw）

> **一句话版**：**三个角度**描述物体在空间里的朝向。**轴机（飞机/无人机）叫法，本项目直接沿用。**

```text
        Z  ↑  （Yaw 绕它转）
           │
           │
           └────────→ X  （Pitch 绕它转）
          /
         Y  （Roll 绕它转）
```

| 角 | 中文 | 绕哪个轴转 | 通俗说法 | 本项目用途 |
|---|---|---|---|---|
| **Pitch** | 俯仰 | **绕 X**（左右轴） | **点头**（前倾/后仰） | ★ **前进 / 后退** |
| **Roll** | 横滚 | **绕 Y**（前后轴） | **歪头**（左倾/右倾） | ★ **左转 / 右转** |
| **Yaw** | 偏航 | **绕 Z**（垂直轴） | **摇头**（左右转向） | ⚠️ **本项目不用（会漂）** |

**记忆法**：把手当飞机头，**点头 = pitch、歪头 = roll、摇头 = yaw**。

### ★ 本项目为什么只用 pitch 和 roll

**因为这两个角有「重力」做绝对参考，不会漂。**
而 yaw 没有参考量 → **必然漂**（见下条）。
→ **手势控制只需要 pitch（前后）和 roll（左右），正好绕开了 yaw 这个坑。**
→ 这是一个**工程上非常聪明的取舍**：不解决不可能解决的问题，而是**换一条不经过它的路**。

## Yaw 零飘

> **一句话版**：**绕垂直轴转的角度，用 MPU6050 算不出来 —— 不是代码问题，是物理限制。**

### ★ 一句话讲清原因

**绕重力轴（垂直轴）旋转时，重力方向在传感器坐标系里「完全不变」。**

```text
不管你怎么绕垂直轴转，Z 轴上永远是 1g，X、Y 上永远是 0
→ 加速度计读出的数据一模一样
→ 它根本无法判断你转了多少度
```

**数学表达**（交接文档里的核心证明）：

```
Rz(ψ)ᵀ · [0, 0, g]ᵀ = [0, 0, g]ᵀ
```

**意思是**：绕 Z 轴旋转 ψ 角的变换矩阵，**作用在重力向量上，结果还是重力向量本身**。
→ **加速度计对 yaw 完全无感。**

### 所以会怎样

- **加速度计对 yaw 无感** → 没有绝对参考可融合
- **只能靠陀螺仪纯积分** → `yaw += gz × dt`
- **陀螺仪有零偏**（静止时也输出零点几个 °/s）→ **积分会累积** → **yaw 单向一直跑**

> ★ **这就是「零飘」**：你明明没动，它自己一直转。

### 三层手法（★ 面试可以按这个思路答）

| 层次 | 方法 | 效果 |
|---|---|---|
| **抑制** | ① **零偏标定**（上电静止测几百次取均值）② 温度补偿 ③ **ZUPT**（检测到静止就把积分掐掉） | 减缓，**不能根治** |
| **根治** | **加磁力计**（用地球磁场做 yaw 的绝对参考） | 根治，但**小车上电机磁干扰大** |
| ★ **绕开** | **本项目不用 yaw** —— 手势只用 pitch/roll | ✅ **最聪明** |

> 📖 **完整 14 章专题**：[[Yaw零飘问题详解]]
>
> 💡 **一句面试金句**：
> **「yaw 漂不是滤波器参数问题，是缺少参考量的问题。滤波器治『抖』不治『漂』。」**

## 互补滤波

> **一句话版**：**「快的信陀螺仪、慢的信加速度计」**，两者按加权比例相加 —— 而这个加权比例，恰好就是一个**高通 + 低通**。

### 为什么需要它

[加速度计与陀螺仪](#加速度计与陀螺仪) 的特性**恰好互补**：

| | 快变（高频） | 慢变 / 长期（低频） |
|---|---|---|
| **陀螺仪** | ✅ 瞬时准、噪声小 | ❌ 零偏积分 → **漂** |
| **加速度计** | ❌ 运动加速度污染 + 噪声大 | ✅ 重力是绝对参考 → **不漂** |

→ **那就各取所长**：**高频段用陀螺仪的积分结果，低频段用加速度计算出的角度。**

### 核心公式（★ 面试重点）

```text
角度 = α × (角度 + 陀螺仪角速度 × dt)  +  (1 − α) × 加速度计算出的角度

其中  α = τ / (τ + dt)        τ = 时间常数
```

**两个系数 `α` 和 `(1−α)` 之和恰好是 1** —— 这就是「**互补**」这个名字的由来。

**逐项含义：**

| 项 | 含义 |
|---|---|
| **`角度 + gz × dt`** | **陀螺仪积分出的角度**（短期准，长期漂） |
| **`atan2(...)` 算出的角度** | **加速度计给的角度**（长期准，短期抖） |
| **`α` 取得大（接近 1）** | **更信陀螺仪** |
| **`τ` 越大** | **越信陀螺仪**（加速度计只做很慢的修正） |

### ★ 为什么叫「互补」—— 频域解释

```text
陀螺仪分支：系数 α        → 高频增益 ≈ 1，低频增益 < 1   （高通特性）
加速度计分支：系数 (1−α)  → 低频增益 = 1，高频增益 < 1   （低通特性）
两者相加：|H(f)| = α + (1−α) = 1                         （全频段增益恒为 1）
```

→ **它其实不是「一个滤波器」，而是「高通 + 低通两条路并行相加」。**
→ 两条路在**截止频率（由 τ 决定）处交叉**：
**低于截止频率信加速度计，高于截止频率信陀螺仪。**

> [!important] τ 怎么选（★ 这就是「调参」）
> **τ 是「从陀螺仪切换到加速度计」的 crossover 时间。**
>
> | τ | 效果 |
> |---|---|
> | **太小**（如 0.01s） | 太信加速度计 → **角度跟着振动抖**（陀螺仪的好处浪费了） |
> | **太大**（如 10s） | 太信陀螺仪 → **漂移抑制不回来**（加速度计的修正太慢） |
> | ★ **典型 0.5 ~ 2 s** | 本项目推荐区间 |
>
> **怎么定 τ？** 看两个误差源的**相对大小**：
> **陀螺仪漂移越小、加速度计噪声越大 → τ 取大一点**（更信陀螺仪）。
>
> 💡 **`α = τ/(τ+dt)`**：`dt = 0.01s`（10ms）、`τ = 1s` → `α = 0.9901`，
> 也就是**每周期 99% 信陀螺仪、1% 信加速度计**。

### 优点与局限

| | 内容 |
|---|---|
| ✅ **优点** | 计算量极小（**几次乘加**，C8T6 无压力）、参数只有一个 `τ`、**直观可解释** |
| ⚠️ **局限** | **没有最优性保证**——`α` 是**人为拍定**的，不是根据噪声统计算出来的 |
| ⚠️ **失效场景** | **长时间持续运动**时加速度计一直不准 → 修正项一直在「拉偏」 → 此时**卡尔曼更好** |

> **PDF 硬性要求 4** 允许「互补滤波**或**卡尔曼滤波」——
> **互补滤波是性价比最高的选择**：效果够用、代码十几行、参数好调。

### 面试常问

- 「互补滤波和低通滤波有什么区别？」→ **互补滤波是两条路相加**（高通 + 低通），**增益恒为 1**；普通低通会**把高频信息整个丢掉**。
- 「为什么不用卡尔曼？」→ 不是不能用，是**互补够用**：卡尔曼要建模 + 调 Q/R 协方差矩阵，**收益在长时间剧烈运动场景才明显**。
- 「α 怎么定？」→ 由 **τ 和采样周期** 决定：`α = τ/(τ+dt)`；**τ 越小越信加速度计**。

> 📖 **可编译的完整代码 + 与卡尔曼的对比**：见 [[模拟面试实录 五阶段 MPU6050与姿态解算]]

## I2C

> **一句话版**：**一根线传时钟、一根线传数据，可以挂很多设备** —— 传感器和 OLED 最常用的接口。

### 为什么需要（它解决了什么问题）

| 接口 | 线数 | 特点 |
|---|---|---|
| **UART** | 2（TX/RX） | **只能一对一** |
| **SPI** | 4（SCK/MOSI/MISO/CS） | 快，但**每个设备要一根片选** |
| ★ **I2C** | **2（SCL/SDA）** | ★ **一条总线挂多个设备，靠地址区分** |

**关键优势**：MPU6050 和 OLED 可以**共用同一条 I2C 总线** ——
因为地址不同（**0x68 vs 0x78**），**互不干扰**。

> 本项目八阶段正是这么做的：**MPU6050 与 OLED 共用 PB8/PB9**，
> 从而**省下 PB10/PB11，保住了按键 K2**。

### ★ 为什么必须「开漏 + 上拉」

```
     VCC
      │
     [R]  ← 上拉电阻（典型 4.7k）
      │
SDA ──┴──────┬──────┬──────
           设备1   设备2
```

- **开漏输出**：设备**只能把线拉低，不能主动拉高**。
- **上拉电阻**：线没人拉低时，**靠电阻把它拉回高电平**。
- ★ **好处**：**任何设备拉低都不会和别的设备冲突**（这叫「线与」）。
  如果用推挽，一个设备输出高、另一个输出低 → **直接短路烧引脚**。

### 时序要点

| 概念 | 含义 |
|---|---|
| **起始条件** | **SCL 高时，SDA 由高变低** |
| **停止条件** | **SCL 高时，SDA 由低变高** |
| **应答（ACK）** | 每传 8 位，接收方**把 SDA 拉低**表示「收到了」 |
| **从机地址** | 7 位地址 + 1 位读写方向 |

## 软件 I2C

> **一句话版**：**不用 STM32 的硬件 I2C 外设，而是用普通 GPIO「手动」翻转出 I2C 时序。**

### 为什么本项目用软件 I2C（★ 这是个工程决策）

| 理由 | 说明 |
|---|---|
| ★ **引脚可自由分配** | 硬件 I2C1 固定在 PB6/PB7。而八阶段 **PB6/PB7 要给右编码器（TIM4）** → **必须挪** |
| **避开 STM32F1 硬件 I2C 的 errata** | F103 的硬件 I2C **有已知问题**（总线死锁等），新手容易卡死 |
| **时序透明、可调试** | 出问题能用示波器一位一位看 |

**代价**：**慢，而且 CPU 全程参与**（一位一位地翻转 + 延时）。

> ⚠️ **本项目真实踩过的坑（八阶段）**：
> 软件 I2C 每位 `Delay_us(10)`，读 14 字节约 **5ms**。
> 一开始把「读 MPU6050」放在 10ms 中断里 → **占 70% 时间**，
> 且**和主循环的 OLED 抢同一条总线 → 花屏、读数错乱、极难复现**。
> → 解决：**拆成 `Attitude_Sample()`（主循环做 I2C）+ `Attitude_FilterUpdate()`（中断做数学）**。
>
> 🎯 **原则：中断必须短、纯、不碰共享资源。**
> **面对共享资源：能靠「消除并发」解决的，就不要靠「加锁」解决。**

# 六阶段：手势控制

## 迟滞（Hysteresis）

> **一句话版**：**用两个阈值代替一个阈值** —— 进入要跨过「高线」，退出要跌破「低线」，中间的带子里状态**保持不变**。

### 为什么需要它

**单阈值的固有缺陷：状态会在阈值附近来回翻。**

```text
设定：pitch > 10° → 前进

手腕角度在 10° 附近微抖：9.8 → 10.2 → 9.9 → 10.1 → 9.7 → 10.3 ...
结果：前进 → 停 → 前进 → 停 → 前进 → 停 ...
     （电机疯狂跳变，发出「哒哒哒」的响声，车一耸一耸）
```

> ⚠️ **这不是「传感器太差」** —— 是**任何「单阈值判决」在噪声环境下的固有缺陷**。
> 换成按键（触点抖动）、换成温控继电器（咔咔响），现象一模一样。

### 解决：双阈值

```text
        ┌─────────── 12° ──── 进入线（超过 12° 才「进入」前进）
        │
        │   ← 迟滞带（12° ~ 7°）：状态保持不变
        │
        └───────────  7° ──── 退出线（低于 7° 才「退出」前进）
```

| 参数 | 本项目取值 |
|---|:--:|
| **进入阈值** | **12°** |
| **退出阈值** | **7°** |

效果：手腕在 **8° ~ 15°** 抖动时，**状态始终是「前进」，不会来回翻**。

### ★ 三个必须理解的点

| # | 要点 |
|:--:|---|
| 1 | ★ **必须有「上次状态」变量** —— 迟滞的本质是**输出依赖历史**，是**有状态**的 |
| 2 | **进入阈值必须 > 退出阈值** —— 写反了会**放大抖动**，比单阈值更糟 |
| 3 | **「停」状态要能从两个方向进入** —— 所以 `STOP` 分支里同时判断正向和反向 |

```c
static Gesture_t s_last = GES_STOP;      /* ★ 迟滞的核心：记住上次状态 */

Gesture_t Gesture_Update(float pitch)
{
    switch (s_last)
    {
    case GES_STOP:
        if (pitch >  GES_ENTER_DEG) { s_last = GES_FORWARD;  }
        if (pitch < -GES_ENTER_DEG) { s_last = GES_BACKWARD; }
        break;
    case GES_FORWARD:
        if (pitch < GES_EXIT_DEG) { s_last = GES_STOP; }
        break;
    case GES_BACKWARD:
        if (pitch > -GES_EXIT_DEG) { s_last = GES_STOP; }
        break;
    }
    return s_last;
}
```

### ★ 迟滞的通用性（面试加分点）

| 场景 | 迟滞的体现 |
|---|---|
| **按键消抖** | 延时 20ms 再读一次（**时间维度**的迟滞） |
| **恒温器** | 26° 开、24° 关（不然继电器咔咔响） |
| **手机电量图标** | 20% 变红、25% 才变回（不然一直闪） |
| **施密特触发器** | 电子学里的同一个概念 |
| **PID 输出限幅** | 也是「不让输出在边界反复横跳」 |

> 🎯 **一句话抽象**：
> **只要一个「连续量 → 离散状态」的判决会被噪声干扰，就应该引入迟滞。**

# 七阶段：速度闭环 PID

## PID

> **一句话版**：**一种「根据差多少，决定加多大劲」的自动控制算法。**
> 三个字母分别管：**现在差多少（P）、过去差了多少（I）、将来会差多少（D）**。

### 为什么需要它

**先看没有 PID 会怎样**：

```text
目标转速 10 rad/s，你给 50% PWM
  → 空载时：转到了 12 rad/s（给多了）
  → 负载时：只转到 6 rad/s（给少了）
  → 电池从 12V 掉到 10V：变成 5 rad/s
```

**问题**：**你不知道该给多少 PWM**。因为「PWM → 转速」的关系**随负载、电压、温度而变**。

**PID 的思路**：**别去猜该给多少，而是「看现在差多少，然后一点点修正」。**

```text
误差 e = 目标值 − 实际值
输出 u = Kp·e + Ki·∫e dt + Kd·de/dt
```

### 三个参数分别干什么（★ 核心）

| 参数 | 中文 | 作用 | 通俗说法 | 副作用 |
|---|---|---|---|---|
| **Kp** | 比例 | **误差越大，输出越大** | 「差得远就使劲推」 | 太大 → **振荡**；太小 → **反应慢** |
| **Ki** | 积分 | **把历史上所有误差累积起来** | 「一直差一点？那我一直加力，直到不差」 | 太大 → **超调、振荡**；★ **会「积分饱和」** |
| **Kd** | 微分 | **看误差的变化速度** | 「快到了？那我提前刹车」 | 太大 → **对噪声极敏感，发抖** |

### ★ 三句话记住三个参数

```
P：现在差多少   → 决定「基础力气」
I：过去差了多少 → 决定「消除最后的静差」
D：将来会差多少 → 决定「刹车，防止冲过头」
```

### ★ 为什么需要 I 项（「静差」问题）

只用 P 的话：假设 `Kp = 1`，目标 10，实际 8 → 输出 = 2。
**这个 2 恰好让实际转速停在 8** → **永远到不了 10**，**永远差 2**。
→ 这叫**静差（稳态误差）**。

**I 项解决它**：误差 2 一直存在 → **积分值一直涨** → 输出一直加大 → **直到误差为 0**。

### ★ 积分饱和（Integral Windup）—— 面试高频

**问题**：如果**目标值突然变得很大**（或电机被卡住），误差会**长期很大** → **积分项累积到非常大的值**。
之后即使误差消失了，**积分项还是要慢慢「泄掉」** → **超调严重、恢复很慢**。

**解决**：

| 方法 | 做法 |
|---|---|
| ★ **积分限幅** | **给积分项设上限**（**本项目用的就是这个**） |
| **积分分离** | 误差很大时**先不用 I**，等接近目标了再启用 |
| **反算（Back-calculation）** | 输出饱和时**把积分项反着拉回来** |

### ★ 位置式 vs 增量式

| 类型 | 公式 | 特点 |
|---|---|---|
| **位置式** | `u = Kp·e + Ki·Σe + Kd·(e−e_last)` | 输出是**绝对量**；**积分要自己限幅**；★ **本项目用** |
| **增量式** | `Δu = Kp(e−e₁) + Ki·e + Kd(e−2e₁+e₂)` | 输出是**增量**；天然抗饱和；**但一次故障会累积** |

### ★ 采样周期是参数的一部分（易被忽略）

```
积分项实际增益 = Ki × Δt
微分项实际增益 = Kd / Δt
```

→ **`Ki`、`Kd` 的数值本身隐含了采样周期。**
→ **换了采样周期，PID 参数必须重新整定！**

**本项目固定 10ms**（放在 TIM1 中断里）就是为了让参数有意义。

### ★ PID 必须放对地方

**反馈量（编码器）在哪里，PID 就要在哪里。**

| 错误做法 | 为什么错 |
|---|---|
| 把手带端当控制器，实际转速传回来 | ❌ 编码器数据要**过蓝牙**，PID 输出再**过蓝牙** → **一个周期两次无线往返，延迟 20ms+，丢一帧就乱** |
| ★ **正确**：PID 放小车端 | ✅ 反馈和输出都在本地，**延迟最小** |

> 🎯 **原则：决策放在信息最全的一端。**

### ★ 整定顺序（工程实践）

```text
① 只开 P：从小到大加，直到出现小幅振荡 → 取振荡值的 60%
② 加 I：从 0 慢慢加，消掉静差 → 一开始会过冲，回调一点
③ 最后加 D：多半用于抑制超调，噪声大时宁可不加（本项目 Kd = 0）
```

**本项目参数**：`Kp = 5.0`、`Ki = 0.5`、`Kd = 0.0`
（比纯 PID 的 8.0 / 1.2 小 —— **因为加了前馈，PID 只负责补差值**）

### 面试常问

- 「P 太大会怎样？」→ **振荡**（在目标值上下反复冲）
- 「I 太大会怎样？」→ **超调 + 振荡 + 恢复慢**（积分饱和）
- 「D 有什么用？为什么有时候不用？」→ 抑制超调，但**放大噪声**。**编码器读数有噪声时，D 会让电机「发抖」** → 宁可不用。
- 「怎么判断参数好不好？」→ 看**阶跃响应**：上升时间、超调量、稳定时间、稳态误差。**用 VOFA+ 看波形**。

## 差速运动学

> **一句话版**：**转向不靠方向盘，靠「两侧轮子速度不一样」**。

### 为什么需要它

用户说的是「**车该往哪走、走多快**」（车身意图），
电机要的是「**你这个轮子转多快**」（轮子转速）。
**中间必须有一层翻译 —— 那就是运动学。**

### 三种运动

```text
【直行】两轮同向同速：   左 ●→      →● 右
【转弯】左轮慢、右轮快： 左 ●→      →→→● 右      （向左偏）
【原地转】两轮等大反向： 左 ←●      →● 右        （车身中心不动）
```

**同一套原理适用于坦克、履带车、双轮平衡车。**

### 符号表

| 符号 | 含义 | 本项目值 |
|---|---|---|
| `v` | 车身中心**线速度**（m/s） | 最大 0.30 |
| `ω` | 车身**角速度**（rad/s） | 最大 2.00 |
| `ω_L` / `ω_R` | 左/右**轮角速度**（rad/s） | — |
| `R` | **轮半径**（m） | 0.0325（65mm 直径） |
| `L` | **轮距**（两轮中心距，m） | 0.200 |

### ★ 两条公式（必须背）

```text
【逆解】车身意图 → 轮子转速   ★ 本项目用这个
    ω_L = (v − (L/2)·ω) / R
    ω_R = (v + (L/2)·ω) / R

【正解】轮子转速 → 车身实际状态
    v = (v_L + v_R) / 2
    ω = (v_R − v_L) / L
```

> ⚠️ **最容易错的地方：`R` 是乘还是除。**
> - **逆解**：车身速度 → 轮**线**速度 → 轮**角**速度 = **除以 `R`**
> - **正解**：轮**角**速度 → 轮**线**速度 → 车身速度 = **乘以 `R`**
>
> **验证方法（超好用）**：**`正解(逆解(v, ω))` 必须等于 `(v, ω)`** ——
> 这叫**往返一致性**，本项目用 gcc 跑了 **54 项断言**验证它。
> **任何数学模块都该做这个自检**：写一个往返，看能不能回到原点。

### 为什么左轮是「减」

**左转（逆时针，`ω > 0`）时，左轮走内圈、右轮走外圈** → 左轮要**慢**、右轮要**快**。

**原地转（`v = 0`）**：
```
ω_L = −(L/2)ω/R      （反转）
ω_R = +(L/2)ω/R      （正转）
→ 两轮等大反向 → 绕车身中心原地打转
```

### 面试常问

- 「两个轮子怎么转弯？」→ **差速**：两侧速度不同，车就偏转。
- 「换成四个电机公式要改吗？」→ **不用**。运动学只关心**两侧**，同侧两个轮**给同样转速**（「两侧分组闭环」）。
- 「为什么手带端发 `(v, ω)` 不发轮速？」→ 发轮速就**必须知道轮径和轮距** → **底盘几何泄漏进协议** → 换底盘手带端要改。

## 能力包络

> **一句话版**：**两个轮子只有一份量程** —— `v` 和 `ω` **不能同时取满**，必须提前「削掉」做不到的部分。

### 为什么需要它

```text
「全速前进 + 急转」时：
   右轮 = v + 转向项   → ★ 先撞上限
   左轮 = v − 转向项   → 还有余量
→ 右轮饱和削顶 → 实际转向能力下降
```

| 不处理的后果（数值实测） | |
|---|---|
| 表现 | 车**往外甩**，转弯半径突然变大，用户觉得「车不听话」 |
| 量化 | 实际 `ω` 退化 ★ **−35.6%** |
| ⚠️ 隐蔽性 | **电机没坏、PID 没报错、程序没崩** —— 只是**转弯变差了** |

> **这种「静默的性能退化」最难查** → **必须在设计层面挡住，而不是等出问题再修。**

### ★ 该牺牲谁：保住 ω，让掉 v

| 理由 | |
|---|---|
| **ω 是「有意图的操作」** | 用户明确在说「我要转」 |
| **v 只是「快慢」** | 快一点慢一点**只是手感** |

### ★ 两段钳位（顺序不能反）

```text
① |ω| ≤ A / (L/2)                  先限 ω（它自己就有物理上限）
② |v| ≤ A − (L/2)·|ω|              再限 v（给定 ω 后还剩多少余量）

其中 A = MOTOR_MAX_WHEEL_SPEED × R
```

| 为什么必须先限 ω | 因为 `Diff_MaxVForOmega()` **依赖 `ω`** —— 反过来的话，`v` 限完了 `ω` 还能再变大，白限 |
|---|---|

### ★ 为什么「只限 v」不够（这是真正的坑）

**看起来没问题**：`ω` 太大 → `v` 被限成 0 → 「安全了」。

**但**：

```text
v = 0、ω = 3 rad/s 时，两轮实际转速：
   ω_L ≈ −9.2 rad/s，ω_R ≈ +9.2 rad/s
   ★ 两轮仍在以接近满速反向旋转！
```

> ### 🎯 `v = 0` 只保证「**车身中心不动**」，**不保证「轮子不转」**。
> **—— 「中间量安全 ≠ 系统安全」。**

**本项目怎么发现这个缺陷的**：

| 项 | 内容 |
|---|---|
| **发现方式** | ★ **穷举扫描 144 万组 `(v, ω)`**（人工根本想不到去试这个组合） |
| **反例数** | 只限 `v`：**86 个**；两段钳位后：**0 个** |
| **教训** | ★ **用「某个中间量被限制了」推断「系统安全」是不可靠的，必须回到最终物理边界验证** |

### 面试常问

- 「`v` 和 `ω` 能同时最大吗？」→ **不能**，两者同时占用两轮量程。
- 「该牺牲谁？」→ **保住 ω、让掉 v**（转向是意图，快慢是手感）。
- 「怎么验证你的限制是对的？」→ **穷举**：扫遍 `(v, ω)` 空间，检查**每一组**算出来的两轮转速是否都 ≤ 最大值。

## 前馈控制

> **一句话版**：**已知的量级，直接给足；不确定的部分，才交给 PID 去补。**

### 为什么需要它

```text
纯 PID 反馈：输出 = Kp·e + Ki·∫e
   → 一开始 e 很大，但输出只能慢慢爬
   → ★ 响应慢；积分还会「先冲过头再回」
```

**根本问题**：**反馈必须「先有误差」，才有力气。**
而有些量**你明明知道**（满 PWM 对应多大轮速），**没必要等误差出现**。

### ★ 前馈系数有解析解（不是试出来的）

```text
前馈占空比 = 目标轮速 / 最大轮速 × 100%
```

```c
float feedforward = target_rads / MOTOR_MAX_WHEEL_SPEED * 100.0f;  /* 已知量级 */
float feedback    = PID_Calc(&pid, target_rads, actual_rads);       /* 只补差值 */
float pwm         = feedforward + feedback;
```

**本项目数值验证（一阶模型仿真）**：

| 方案 | 100ms 时 | 稳态 |
|---|---|---|
| **纯反馈** | 明显滞后 | 靠积分慢慢消静差 |
| ★ **前馈 + 反馈** | **进入 ±5%** | **静差 −2.6%** |

> ⚠️ **这是仿真值，不是实测值。**

### ★ 加了前馈，PID 参数必须调小

```c
/* 纯反馈 */      Kp = 8.0   Ki = 1.2
/* 前馈 + 反馈 */ Kp = 5.0   Ki = 0.5   Kd = 0.0
```

| 为什么 | |
|---|---|
| 前馈已承担主要输出 | PID 只需补**残差**，误差本来就不大 |
| ★ **不调小的后果** | `前馈 + 过大的 PID` → **总输出过大 → 振荡甚至饱和** |

> 🎯 **「结构变了，参数就要重来」** ——
> **这也是 PID 参数不能跨系统复用的原因。**

### 面试常问

- 「前馈和反馈的区别？」→ 前馈**开环、基于模型**（不用等误差）；反馈**闭环、基于误差**（能纠正模型不知道的偏差）。
- 「前馈能单独用吗？」→ 不行。前馈依赖模型准确，**模型错了它不知道**；**必须留反馈兜住**。
- 「加了前馈还要重新调 PID 吗？」→ ★ **必须**。
