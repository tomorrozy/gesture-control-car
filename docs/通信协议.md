# 通信协议

手柄端与小车端通过 nRF24L01 单向传输，**手柄 → 小车**，周期 **100 ms**。

---

## 一、帧格式

固定 13 字节有效帧：

| 偏移 | 字段 | 类型 | 长度 | 说明 |
|---|---|---|---|---|
| 0 | `HEAD` | `uint8` | 1 | 帧头，固定 `0xA5` |
| 1 | `LEN` | `uint8` | 1 | 有效载荷长度，固定 `0x09` |
| 2 | `pitch` | `float`（小端） | 4 | 俯仰角，单位度，限幅 ±80° |
| 6 | `roll` | `float`（小端） | 4 | 横滚角，单位度，限幅 ±80° |
| 10 | `gesture` | `uint8` | 1 | 手势指令，见下表 |
| 11 | `CHK` | `uint8` | 1 | 校验值 = `buf[1] ^ buf[2] ^ ... ^ buf[10]` |
| 12 | `TAIL` | `uint8` | 1 | 帧尾，固定 `0x0D` |

### 手势编码

| 值 | 宏 | 条件 |
|---|---|---|
| 0 | `GESTURE_NONE` | 未使用 |
| 1 | `GESTURE_FWD` | `pitch > 15°` |
| 2 | `GESTURE_BACK` | `pitch < -15°` |
| 3 | `GESTURE_LEFT` | `roll > 15°` |
| 4 | `GESTURE_RIGHT` | `roll < -15°` |
| 5 | `GESTURE_STOP` | 其余情况 |

> 实际控制逻辑**不使用** `gesture` 字段，而是直接用 `pitch`/`roll` 连续量做速度映射。
> `gesture` 仅用于 OLED 显示和调试，保留给需要开关量控制（比如抓取、鸣笛）的扩展场景。

---

## 二、打包流程（手柄端）

```c
// 1. 取角度并取反（传感器安装方向相反）
pitch = angle.Pitch * -1.0f;
roll  = angle.Roll  * -1.0f;

// 2. 限幅
clamp(pitch, -80.0f, 80.0f);
clamp(roll,  -80.0f, 80.0f);

// 3. 手势映射（阈值 15°）
gesture = Gesture_Map(pitch, roll);

// 4. 组帧
out[0]  = 0xA5;
out[1]  = 9;
memcpy(out + 2, &pitch, 4);   // 小端 float
memcpy(out + 6, &roll,  4);
out[10] = gesture;

// 5. XOR 校验（只算 buf[1] .. buf[10]）
for (i = 1; i < 11; i++) chk ^= out[i];
out[11] = chk;
out[12] = 0x0D;

// 6. 发送（无线层实际发 32 字节缓冲，剩余补 0）
NRF24L01_SendData(out, 32);
```

发送节拍由 `TIM4` 的 1 ms 中断累加 `Time_ms`，超过 100 时清零并发送一次。

---

## 三、解包流程（小车端）

`task_rx` 每 20 ms 轮询一次接收 FIFO，**四项校验全过才采信**，任一失败整帧丢弃：

```c
if (len != 13)                    return -1;   // 长度
if (buf[0] != 0xA5)               return -1;   // 帧头
if (buf[1] != 9)                  return -1;   // 载荷长度
if (buf[12] != 0x0D)              return -1;   // 帧尾
for (i = 1; i < 11; i++) chk ^= buf[i];
if (chk != buf[11])               return -1;   // 校验和

memcpy(&pitch,   buf + 2, 4);
memcpy(&roll,    buf + 6, 4);
gesture = buf[10];
```

解析成功后再次限幅 ±80°，然后用互斥量 `xMutex` 保护地写入全局变量 `g_pitch` / `g_roll` / `g_gesture`，供 `task_ctrl` 和 `task_disp` 读取。

## 四、无线层参数

| 参数 | 手柄端（发） | 小车端（收） |
|---|---|---|
| 射频通道 `RF_CH` | 40 | 40 |
| 发送地址 `TX_ADDR` | `0x11 11 11 11 11`（`TX_ADDR1`） | — |
| 接收管道 0 地址 | — | `0x11 11 11 11 11` |
| 接收管道 1 地址 | — | `0x22 22 22 22 22`（保留给第二个手柄） |
| ACK 地址 `RX_ADDR` | `0xAA AA AA AA AA` | — |
| 数据宽度 | 32 字节 | 32 字节 |

小车端用**多通道**接收：通过读 `STATUS` 寄存器的 `RX_P_NO` 位判断数据来自哪个管道，因此理论上可以同时接两个手柄（对应 `遥控` 里 `TX_ADDR1` / `TX_ADDR2` 两套地址）。

---

## 五、修改协议时注意

1. **两端同步改**：`遥控/User/main.c` 和 `FreeRTOS小车/USER/main.c` 里各有一份协议定义（当前是内联复制的，没有共用头文件）。
2. **`LEN` 与 `FRAME_LEN` 必须一致**：`PAYLOAD_LEN = 9`，`FRAME_LEN = 4 + 9 = 13`。
3. **float 字节序**：两端都是 ARM 小端，直接 `memcpy` 即可；如果换平台要显式处理字节序。
4. **校验范围**：`CHK` 只覆盖 `buf[1]..buf[10]`，不含帧头帧尾；改字段时要同步改循环上界。
5. **发送长度**：无线层固定发 32 字节，接收端按 13 字节解析，多余字节被忽略。
