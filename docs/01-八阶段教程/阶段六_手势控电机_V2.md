## 📡 本章前置知识点雷达

> [!info] 预习指南：在啃代码之前，先认识这些“硬核名词”
> 本章围绕以下 5 个概念展开。

| 知识点名称 | 一句话通俗解释 | 在本章代码中的角色 |
| :--- | :--- | :--- |
| **阈值分类** | 连续角度按门槛切成几种动作。 | `Gesture_Map`，阈值 15° |
| **判定优先级** | 多个条件同时满足先看谁。 | 先判 pitch，再判 roll |
| **迟滞** | 进门槛高、出门槛低，避免边界抖动。 | 代码里没有（本章给补法） |
| **连续量 vs 离散量** | 连续量给大小，离散量只给方向。 | 遥控发 gesture，车用 pitch/roll |
| **备用指令通道** | 发了、存了但没人用的字段。 | `g_gesture` 只写不读 |

## 三、逐行精讲

### 3.1 手势编号定义（遥控 main.c 16–21 行）

```c
#define GESTURE_NONE   0
#define GESTURE_FWD    1
#define GESTURE_BACK   2
#define GESTURE_LEFT   3
#define GESTURE_RIGHT  4
#define GESTURE_STOP   5
```

【第 16 行】0 = NONE：定义存在，但映射从不返回它。
【第 17 行】1 = 前进。
【第 18 行】2 = 后退。
【第 19 行】3 = 左转。
【第 20 行】4 = 右转。
【第 21 行】5 = 停止，也是小车端 `g_gesture` 的初值。
【类型补充】小车端 `volatile uint8_t g_gesture`（`main.c:96`）；遥控端局部 `uint8_t gesture`（`main.c:129`）。

> [!abstract] 人话翻译
> 这 6 个编号是“暗号”，两端必须一致；改一个数就等于改协议语义。

### 3.2 手势映射（遥控 main.c 62–73 行）

```c
static uint8_t Gesture_Map(float pitch, float roll)
{
    const float TH = 15.0f;

    /* 如果左右反了，就互换 LEFT 和 RIGHT 的返回值 */
    if (pitch >  TH) return GESTURE_FWD;
    if (pitch < -TH) return GESTURE_BACK;
    if (roll  >  TH) return GESTURE_LEFT;
    if (roll  < -TH) return GESTURE_RIGHT;

    return GESTURE_STOP;
}
```

【第 62 行】`static uint8_t`：仅本文件可见，返回 8 位编号。
【第 64 行】`TH = 15.0f`。
【第 66 行】关键注释：**左右反了就互换 LEFT/RIGHT 的返回值**——作者留的“方向后门”。
【第 67 行】pitch 超正门槛 → 前进（先判前后）。
【第 68 行】pitch 超负门槛 → 后退。
【第 69 行】roll 超正门槛 → 左。
【第 70 行】roll 超负门槛 → 右。
【第 72 行】都没超 → 停止（5，不是 0）。

> [!warning] 第 66 行注释与车端 `REVERSE_TURN` 是**两套独立开关**
> 同时改会互相抵消；排查左右反时只改一处。

> [!abstract] 人话翻译
> 这是分类器、不是控制器：只回答“往哪”，不回答“多快”。pitch 优先，斜推时左右信息会被丢掉。

### 3.3 主循环取值与限幅（遥控 main.c 133–147 行）

```c
	OLED_Clear();
	MPU6050_GetAngle(&angle);
	MPU6050_GetData(&AX, &AY, &AZ, &GX,& GY, &GZ);
    pitch = angle.Pitch * -1.0f;
    roll  = angle.Roll  * -1.0f;
    if (pitch >  80.0f) pitch =  80.0f;
    if (pitch < -80.0f) pitch = -80.0f;
    if (roll  >  80.0f) roll  =  80.0f;
    if (roll  < -80.0f) roll  = -80.0f;
    gesture = Gesture_Map(pitch, roll);
```

【第 133 行】清显存。
【第 134 行】取滤波后的角度。
【第 135 行】再读原始值（仅显示）。
【第 138–139 行】整体取反适配安装方向。
【第 141–144 行】限幅 ±80。
【第 147 行】映射得 0~5。

> [!abstract] 人话翻译
> 每轮：取角度 → 取反 → 限幅 → 判手势。`× -1.0f` 是装配补丁，不取反就前后左右全反。

### 3.4 显示手势编号（遥控 main.c 149–153 行）

```c
	OLED_ShowSignedNum(88, 1,  (int)pitch, 3, OLED_8X16);
	OLED_ShowSignedNum(88, 16, (int)roll,  3, OLED_8X16);
    OLED_ShowString(1, 32, "G:", 16);
    OLED_ShowNum(24, 32, gesture, 2, OLED_8X16);
```

【第 150 行】显示 pitch 整数。
【第 151 行】显示 roll 整数。
【第 152 行】显示 “G:”。
【第 153 行】显示手势编号（00~05）。

> [!abstract] 人话翻译
> 这是手势唯一的可视化窗口；屏幕显示 `(int)`，小数抖动看不见，判断稳不稳要看原始 float。

### 3.5 把 gesture 塞进协议并发出去（遥控 main.c 156–165 行）

```c
	if(Time_ms > 100)
	{
        Time_ms = 0;
        payload.pitch   = pitch;
        payload.roll    = roll;
        payload.gesture = gesture;
        Protocol_Pack(&payload, tx_frame);
        NRF24L01_SendData(tx_frame, 32);
	}
```

【第 156 行】`Time_ms > 100`：10 Hz 发送节拍。
【第 158 行】归零重计时。
【第 159–160 行】填 pitch、roll。
【第 161 行】填 gesture。
【第 162 行】打包 13 字节有效帧。
【第 165 行】发 32 字节（第 10 字节是 gesture）。

> [!abstract] 人话翻译
> 手势确实上了车：第 10 字节跟着 32 字节包飞向小车。

### 3.6 小车收下 gesture —— 然后锁进抽屉（main.c 96、202 行）

```c
volatile uint8_t g_gesture = GESTURE_STOP;
...
                g_gesture = pl.gesture;
```

【第 96 行】定义全局，初值“停止”。
【第 202 行】解包成功即更新。

> [!warning] 全工程只有这两处
> 搜索 `g_gesture` 只命中“定义”与“赋值”，**没有任何读取**——遥控算的手势到车端就被存起来不用。

> [!abstract] 人话翻译
> 链路走到 `g_gesture` 就断了，是“备用指令通道”——留着，没通车。

### 3.7 真正驱动电机的是连续量（main.c 230–259 行，节选）

```c
        if (pitch > DEAD_ZONE) {
            speed_x = ((pitch - DEAD_ZONE) / (80.0f - DEAD_ZONE)) * MAX_SPEED;
        } else if (pitch < -DEAD_ZONE) {
            speed_x = ((pitch + DEAD_ZONE) / (80.0f - DEAD_ZONE)) * MAX_SPEED;
        }
        ...
#if REVERSE_TURN
        speed_y = -speed_y;
#endif
        ...
        targetL = speed_x + speed_y;
        targetR = speed_x - speed_y;
```

【第 233–237 行】pitch 算前后速度（死区 10°）。
【第 239–243 行】roll 算转向速度（死区 15°）。
【第 245–247 行】`REVERSE_TURN` 取反。
【第 252–253 行】差速合成。

> [!abstract] 人话翻译
> 小车根本不看 gesture，它拿 pitch/roll 重算“连续速度”；遥控说“前进”，车是按角度算具体速度——两套逻辑各自独立。

### 3.8 小车状态显示：第三套阈值（main.c 17–18、324–346 行）

```c
#define SCREEN_FLIP 1     // 屏幕倒装(1)，正装(0)
#define REVERSE_TURN 1    // 左右反了改这里(0变1)
```

【第 17 行】`SCREEN_FLIP`：只影响显示排版。
【第 18 行】`REVERSE_TURN`：影响控制（差速取反）与显示（左右文字）两处。

```c
        int is_stop     = (fabs(pitch) <= 10.0f);
        int is_forward  = (pitch > 10.0f);
        int is_backward = (pitch < -10.0f);
        int is_straight = (fabs(roll) <= 15.0f);
#if REVERSE_TURN
        int is_right    = (roll < -15.0f);
        int is_left     = (roll > 15.0f);
#else
        int is_right    = (roll > 15.0f);
        int is_left     = (roll < -15.0f);
#endif
        if(is_stop && is_straight)          strcpy(status, "停止");
        else if(is_forward && is_straight)  strcpy(status, "前进");
        ...
```

【第 324–326 行】pitch 三档（±10°）。
【第 328 行】roll ±15° 判直行。
【第 329–335 行】`#if REVERSE_TURN` 两套左右定义。
【第 337–346 行】9 分支 + `else` 兜底。

> [!abstract] 人话翻译
> 同一份姿态被解释了三遍：遥控 `Gesture_Map`（15/15）、车控制（10/15）、车显示（10/15）。阈值散落三处，改一处记得另两处。

## 四、硬件与现象对照（含“三屏不一致”推导）

| 操作 | 遥控 OLED | 小车 OLED | 车轮 |
|---|---|---|---|
| 平放 | `G:05` | 停止 | 停 |
| pitch = 12° | **`G:05`（≤15 判停）** | **“前进”（>10）** | **PWM 抬到 30%** |
| pitch = 16° | `G:01` | 前进 | 走 |
| 侧翻 16° | `G:03/04` | 原地转 | 两轮反向 |
| 15° 附近摆 | `G` 1/5 反复跳 | 状态跳变 | 一顿一顿 |

> [!warning] 以 `pitch=12°` 为例（算术推导）
> 遥控：15° 门槛 → 判停（G=5）。
> 车控制：`speed_x=(12−10)/70×100≈2.9`。
> 起转补偿：目标 >0.1 就把 PWM 抬到 **30**。
> 结果：**屏幕说停，车却以约 30% 走**。
> 另 `10.0°→10.1°`：目标 0→0.14，跨过 0.1 直接跳到 30%，中间无过渡。

> [!warning] 待确认（防幻觉）
> 物理“前进/左转”取决于电机接线、`REVERSE_TURN` 与遥控 `× -1.0f`；代码只给逻辑方向，实物朝向需上车确认。

## 五、本阶段缺口与补法

| 项目 | 现状 | 补法 |
|:--:|:--:|---|
| 无线（有线连接） | 直接无线 | 有线需遥控端补串口（阶段一） |
| 电机端用 gesture | 不读 | 读 `g_gesture` 做离散档位 |
| 迟滞 | 无 | 见下方示例 |
| 心跳 | 无 | 小车端超时停车 |

```c
/* ⚠️ 新增示例：让 Gesture_Map 带迟滞（进 20°、退 12°） */
static uint8_t last_gesture = GESTURE_STOP;
static uint8_t Gesture_Map_Hyst(float pitch, float roll)
{
    const float TH_IN  = 20.0f;
    const float TH_OUT = 12.0f;
    uint8_t g = last_gesture;
    if (pitch >  TH_IN) g = GESTURE_FWD;
    else if (pitch < -TH_IN) g = GESTURE_BACK;
    else if (fabs(pitch) < TH_OUT) {
        if (roll >  TH_IN) g = GESTURE_LEFT;
        else if (roll < -TH_IN) g = GESTURE_RIGHT;
        else if (fabs(roll) < TH_OUT) g = GESTURE_STOP;
    }
    last_gesture = g;
    return g;
}
```

【新增】`Gesture_Map_Hyst` 不存在于源码；`fabs` 需 `<math.h>`（源码 `main.c` 已 include）。
【已知简化】`12° ≤ |pitch| < 20°` 时停在“保持上次手势”，这段时间左右被忽略；工程上应给 pitch/roll 各自独立迟滞。

> [!abstract] 人话翻译
> 迟滞=“进门难、出门也难”：进 20° 才切换，退回 12° 才复位，用一点响应速度换稳定。
