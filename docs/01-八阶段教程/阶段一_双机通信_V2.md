## 📡 本章前置知识点雷达

> [!info] 预习指南：在啃代码之前，先认识这些“硬核名词”

| 知识点名称 | 一句话通俗解释 | 在本章代码中的角色 |
| :--- | :--- | :--- |
| **UART 异步串行** | 两根线按约定速度一位一位传，不共享时钟。 | `usart.c` 初始化 PA9/PA10 |

### 3.2 fputc：把字符塞进串口（usart.c 27–32 行）

```c
int fputc(int ch, FILE *f)
{
	while((USART1->SR&0X40)==0);//循环发送,直到发送完毕
    USART1->DR = (u8) ch;
	return ch;
}
```

【第 27 行】重定义 C 库“输出一个字符”。
【第 28 行】函数体开始。
【第 29 行】等 `SR` 的 bit6（TC，发送完成），没完成原地等。
【第 30 行】把字符写进 `DR`，硬件按波特率发出。
【第 31 行】返回字符。
【第 32 行】函数结束。

> [!abstract] 人话翻译
> `printf("Hi")` 会逐字符调用它：先等上一字节彻底发完（TC），再写新字节进数据寄存器，文字就从 PA9 流出。`0x40` 等的是“发完”，比等“寄存器空”更稳。

### 3.5 接收状态机前半（usart.c 103–119 行）

```c
void USART1_IRQHandler(void)
{
	u8 Res;

	if(USART_GetITStatus(USART1, USART_IT_RXNE) != RESET)
		{
		Res =USART_ReceiveData(USART1);

		if((USART_RX_STA&0x8000)==0)
			{
			if(USART_RX_STA&0x4000)
				{
				if(Res!=0x0a)USART_RX_STA=0;
				else USART_RX_STA|=0x8000;
				}
```

【第 103 行】中断函数名必须与向量表一致。
【第 104 行】函数体开始。
【第 105 行】`u8 Res;` 暂存字节。
【第 107 行】确认是 RXNE 引起中断。
【第 109 行】读走数据（读 DR 清 RXNE，防反复进中断）。
【第 111 行】bit15 = 接收完成。
【第 113 行】bit14 = 已收到过 0x0D。
【第 115 行】应是换行却不是 → 整帧作废。
【第 116 行】回车+换行齐 → 置完成位。
【第 119 行】未收到 0x0D 的分支开始。

> [!abstract] 人话翻译
> 中断里先确认“确实收到字节”，立刻读走；再看状态位：若已见回车，就只等换行——是换行举旗“收完”，不是就作废。

### 3.7 协议定义与结构体（main.c 22–40 行）

```c
/* ==================== 通信协议（内联） ==================== */
#define FRAME_HEAD        0xA5
#define FRAME_TAIL        0x0D

#define GESTURE_NONE   0
#define GESTURE_FWD    1
#define GESTURE_BACK   2
#define GESTURE_LEFT   3
#define GESTURE_RIGHT  4
#define GESTURE_STOP   5

#define PAYLOAD_LEN  9
#define FRAME_LEN    (4 + PAYLOAD_LEN)   /* = 13 */

typedef struct {
    float   pitch;
    float   roll;
    uint8_t gesture;
} AttitudePayload_t;
```

【第 22 行】协议直接内联在 `main.c`，没有独立协议文件。
【第 23–24 行】帧头 `0xA5`、帧尾 `0x0D`。
【第 26–31 行】6 个手势编号 0~5。
【第 33 行】数据区 9 字节。
【第 34 行】整帧 = 4 + 9 = 13。
【第 36–40 行】结构体：两个 `float` + 一个 `uint8_t`。

> [!abstract] 人话翻译
> 13 字节 = 帧头 1 + 长度 1 + pitch 4 + roll 4 + gesture 1 + 校验 1 + 帧尾 1。`PAYLOAD_LEN=9` 是数据区长度，不是整帧长度——最容易记混。

### 3.8 解包：四道验身再取值（main.c 42–55 行）

```c
static int Protocol_Unpack(const uint8_t *buf, int len, AttitudePayload_t *p)
{
    uint8_t chk = 0, i;
    if (len != FRAME_LEN)             return -1;
    if (buf[0] != FRAME_HEAD)         return -1;
    if (buf[1] != PAYLOAD_LEN)        return -1;
    if (buf[len - 1] != FRAME_TAIL)   return -1;
    for (i = 1; i < 2 + PAYLOAD_LEN; i++) chk ^= buf[i];
    if (chk != buf[2 + PAYLOAD_LEN])  return -1;
    memcpy(&p->pitch,   buf + 2, 4);
    memcpy(&p->roll,    buf + 6, 4);
    p->gesture = buf[10];
    return 0;
}
```

【第 42 行】`static int`：仅本文件可见，成功 0、失败 −1。
【第 43–44 行】函数体与变量。
【第 45 行】长度必须 13。
【第 46 行】帧头必须 `0xA5`。
【第 47 行】长度字节必须 9。
【第 48 行】末字节必须 `0x0D`。
【第 49 行】第 1~10 字节逐字节异或。
【第 50 行】与第 11 字节比对。
【第 51 行】第 2~5 字节 → `pitch`。
【第 52 行】第 6~9 字节 → `roll`。
【第 53 行】第 10 字节 → `gesture`。
【第 54–55 行】返回成功 / 函数结束。

> [!abstract] 人话翻译
> 解包像验票：长度、票头、编号、撕口，最后对防伪码（异或）。用 `memcpy` 避免 float 对齐问题。

### 3.9 打包：清黑板、填格子、算防伪码（遥控 main.c 75–93 行）

```c
static int Protocol_Pack(const AttitudePayload_t *p, uint8_t *out)
{
    uint8_t chk = 0, i;
    memset(out, 0, 32);
    out[0] = FRAME_HEAD;
    out[1] = PAYLOAD_LEN;
    memcpy(out + 2, &p->pitch, 4);
    memcpy(out + 6, &p->roll,  4);
    out[10] = p->gesture;
    for (i = 1; i < 2 + PAYLOAD_LEN; i++) chk ^= out[i];
    out[2 + PAYLOAD_LEN] = chk;
    out[3 + PAYLOAD_LEN] = FRAME_TAIL;
    return FRAME_LEN;
}
```

【第 75 行】打包函数。
【第 76–77 行】函数体与变量。
【第 79 行】`memset(out, 0, 32)`：清 **32** 字节（运输层定长）。
【第 81–82 行】填帧头、数据区长度。
【第 83–84 行】两个 float。
【第 85 行】手势放第 10 字节。
【第 88–89 行】异或校验，放第 11 字节。
【第 90 行】帧尾放第 12 字节。
【第 92 行】返回有效长度 13。
【第 93 行】函数结束。

> [!abstract] 人话翻译
> 打包与解包完全对称：先擦 32 字节黑板，再按格子填；返回 13 告诉调用方“前 13 字节有效”。

## 四、硬件与现象对照

| 代码配置 | 引脚 | 外部接什么 | 现象 |
|---|---|---|---|
| `AF_PP` | PA9 | → USB-TTL 的 RXD | 串口助手能收到字符 |
| `IN_FLOATING` | PA10 | ← USB-TTL 的 TXD | 板子能收电脑发的字节 |
| 115200 8N1 | — | 助手设 115200 | 参数不一致就乱码 |
| 接收中断 | — | — | 发 `abc\r\n` 后 `USART_RX_STA` 变 `0x8003` |

> [!warning] 盲区提示
> 代码只说明 PA9/PA10 被配成串口，**没有排针位置和 USB-TTL 接线**。以板子丝印为准：PA9→RXD、PA10→TXD、GND→GND。
