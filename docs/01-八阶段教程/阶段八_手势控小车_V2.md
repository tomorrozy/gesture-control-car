## 📡 本章前置知识点雷达

> [!info] 预习指南：在啃代码之前，先认识这些“硬核名词”
> 本章围绕以下 5 个概念展开。

| 知识点名称 | 一句话通俗解释 | 在本章代码中的角色 |
| :--- | :--- | :--- |
| **差速转向** | 左右轮速度不同，车就会转弯。 | `targetL = x + y`、`targetR = x − y` |
| **差速归一化** | 两轮目标超量程时等比缩小，保住比例。 | 代码里没有（本章给补法） |
| **变化率限制** | 让目标慢慢靠近，不一步跳到位。 | 代码里没有（本章给补法） |
| **死区 + 线性映射** | 小角度当 0，超过门槛按比例给速度。 | `DEAD_ZONE=10`、`TURN_THRESHOLD=15` |
| **任务优先级** | 收包 > 控制 > 显示。 | `PRIO_RX=3 > PRIO_CTRL=2 > PRIO_DISP=1` |

## 三、逐行精讲

### 3.1 两个开关宏（main.c 17–18 行）

```c
#define SCREEN_FLIP 1     // 屏幕倒装(1)，正装(0)
#define REVERSE_TURN 1    // 左右反了改这里(0变1)
```

【第 17 行】`SCREEN_FLIP`：屏幕装反时把显示四行**行坐标反写**（48↔1、32↔16），只影响显示。
【第 18 行】`REVERSE_TURN`：把转向分量取反，影响**控制**（差速前 `speed_y = -speed_y`）与**显示**（`is_right/is_left`）两处。

> [!abstract] 人话翻译
> 这两个是“装配适配开关”。`SCREEN_FLIP` 纯显示、安全；`REVERSE_TURN` 改的是车的行为，改完必须上车验证。注意遥控端 `Gesture_Map` 第 66 行还留了“互换 LEFT/RIGHT”的后门，与 `REVERSE_TURN` 是两套独立开关，同时改会抵消。

### 3.2 映射常量（main.c 217–221 行）

```c
    const float DEAD_ZONE       = 10.0f;
    const float TURN_THRESHOLD  = 15.0f;
    const float MAX_SPEED       = 100.0f;
    const float MIN_SPEED       = 20.0f;
```

【第 217 行】前后死区 10°。
【第 218 行】转向死区 15°（转向更钝，抗手抖）。
【第 220 行】速度上限 100。
【第 221 行】`MIN_SPEED=20`：声明后**再没出现**，是死变量。

> [!abstract] 人话翻译
> 真正的最小输出不是 20，而是起转补偿里写死的 30。想调最低速，改那两处魔法数。

### 3.3 姿态 → speed_x / speed_y（main.c 230–243 行）

```c
        float speed_x = 0.0f; 
        float speed_y = 0.0f; 

        if (pitch > DEAD_ZONE) {
            speed_x = ((pitch - DEAD_ZONE) / (80.0f - DEAD_ZONE)) * MAX_SPEED;
        } else if (pitch < -DEAD_ZONE) {
            speed_x = ((pitch + DEAD_ZONE) / (80.0f - DEAD_ZONE)) * MAX_SPEED;
        }

        if (roll > TURN_THRESHOLD) {
            speed_y = ((roll - TURN_THRESHOLD) / (80.0f - TURN_THRESHOLD)) * MAX_SPEED;
        } else if (roll < -TURN_THRESHOLD) {
            speed_y = ((roll + TURN_THRESHOLD) / (80.0f - TURN_THRESHOLD)) * MAX_SPEED;
        }
```

【第 230–231 行】先清零，避免残留。
【第 233 行】超过死区才算前进。
【第 234 行】线性映射：45° → 50，80° → 100。
【第 235–236 行】负方向同理。
【第 239–243 行】roll 用同样方式算转向分量（分母 80−15）。

> [!abstract] 人话翻译
> 先把死区减掉，再按“最大角-死区”归一化，乘 100。两个分量都能各自到 100。

### 3.4 差速合成（main.c 245–254 行）

```c
#if REVERSE_TURN
        speed_y = -speed_y; 
#endif

        if (fabs(speed_x) < 0.1f && fabs(speed_y) < 0.1f) {
            targetL = 0; targetR = 0;
        } else {
            targetL = speed_x + speed_y;
            targetR = speed_x - speed_y;
        }
```

【第 245–247 行】按宏把转向分量取反。
【第 249 行】两个分量都接近 0 → 判停。
【第 250 行】目标清零。
【第 252 行】左轮 = 前进 + 转向。
【第 253 行】右轮 = 前进 − 转向。

> [!abstract] 人话翻译
> 差速转向就两行：一个加、一个减。前进时两轮同号，转向时一加一减形成差速，原地转时恰好相反。

### 3.5 目标限幅（main.c 256–259 行）

```c
        if (targetL > MAX_SPEED)  targetL = MAX_SPEED;
        if (targetL < -MAX_SPEED) targetL = -MAX_SPEED;
        if (targetR > MAX_SPEED)  targetR = MAX_SPEED;
        if (targetR < -MAX_SPEED) targetR = -MAX_SPEED;
```

【第 256–257 行】左轮夹在 ±100。
【第 258–259 行】右轮夹在 ±100。

> [!warning] 各自截断会破坏差速比例（算术推导）
> 例：`pitch=80°` 得 `speed_x=100`，`roll=60°` 得 `speed_y≈69.2`。
> 原始差速 = `(169.2, 30.8)`；各自截断后 = `(100, 30.8)`，比例从 5.5:1 变成 3.25:1 → **转弯半径被改变**。
> 正确做法：等比缩小，见 3.8。

> [!abstract] 人话翻译
> 限幅是安全必须的，但“各自砍”会让左右比例失真，表现为“大角度斜推时车突然变直/打转”。

### 3.6 闭环与输出（main.c 268–296 行，节选）

```c
        pid_left.target  = targetL;
        pid_right.target = targetR;
        pwm_L_temp = PID_Calc(&pid_left,  g_act_left);
        pwm_R_temp = PID_Calc(&pid_right, g_act_right);
        ...
        Motor_SetPWM(1, (int16_t)pwm_L_temp);
        Motor_SetPWM(2, (int16_t)pwm_R_temp);
```

【第 268–269 行】左右目标交给各自的 PID。
【第 271–272 行】各用各的编码器反馈算 PWM。
【第 274–293 行】起转补偿（左轮 274–280、右轮 282–288）与再限幅（290–293）——本段 `...` 省略，详见 [[阶段七_主教程_速度闭环PID_V1]] 3.8。
【第 295–296 行】写入电机。

> [!abstract] 人话翻译
> 差速的“执行层”就是两个互不干扰的速度环。目标同源、反馈独立，所以一轮打滑不会拖死另一轮，但也**没有直行同步**。补偿环节会把“想走”的最小输出抬到 30%，这一点由阶段七逐行讲。

### 3.7 九种状态显示（main.c 324–346 行）

```c
        int is_stop     = (fabs(pitch) <= 10.0f);
        int is_forward  = (pitch > 10.0f);
        int is_backward = (pitch < -10.0f);
        int is_straight = (fabs(roll) <= 15.0f);
#if REVERSE_TURN
        int is_right    = (roll < -15.0f);
        int is_left     = (roll > 15.0f);
#else
        int is_right    = (roll > 15.0f);
        int is_left     = (roll < -15.0f);
#endif
        if(is_stop && is_straight)          strcpy(status, "停止");
        else if(is_forward && is_straight)  strcpy(status, "前进");
        else if(is_backward && is_straight) strcpy(status, "后退");
        else if(is_stop && is_right)        strcpy(status, "原地右转");
        ...
```

【第 324–326 行】pitch 三档（±10°）。
【第 328 行】roll 是否在 ±15° 内（直行）。
【第 329–335 行】`#if REVERSE_TURN` 决定 `is_right/is_left` 的符号（两套定义互斥）。
【第 337–346 行】3×3 组合成 9 种文字，最后 `else` 兜底“停止”。

> [!abstract] 人话翻译
> 显示层又判了一遍，阈值 10/15 与控制层一致；但遥控端 `Gesture_Map` 是 15/15，所以三屏仍可能不一致。

### 3.8 归一化补法（⚠️ 工程里没有）

```c
        /* 新增：接在差速合成之后、限幅之前 */
        float maxv = fabsf(targetL);
        if (fabsf(targetR) > maxv) maxv = fabsf(targetR);
        if (maxv > MAX_SPEED) {
            float k = MAX_SPEED / maxv;
            targetL *= k;
            targetR *= k;
        }
```

【新增第 1–2 行】取两者绝对值最大者。
【新增第 3–6 行】超过 100 就等比缩小，保住原始比例。

> [!warning] 与源码的差异（实现提示）
> 这个补法用 `fabsf`（float 版），源码判零用 `fabs`（double 版，`main.c:249`）；两者都能编译，**都要 `<math.h>`**（源码 `main.c:14` 已 include）。

> [!abstract] 人话翻译
> 截断是“砍掉超出的部分”，归一化是“整体缩小”。前者改比例，后者不改。修完后大角度斜推的转弯半径才稳定。

### 3.9 变化率限制补法（⚠️ 工程里没有）

```c
static float slew(float cur, float want, float step)
{
    if (want > cur + step) return cur + step;
    if (want < cur - step) return cur - step;
    return want;
}
```

【新增】每 20 ms 让目标最多变化 `step`，`step` 取 5~10（**经验值，不是源码常量**）。
【效果】起步不窜、停车不点头；代价是从 0 到 100 需要约 400 ms（`step=5`）。

> [!abstract] 人话翻译
> 这是“电子油门”：你给的是愿望值，真实目标被斜坡追着走。平稳与跟手在这里取舍。

### 3.10 整机任务框架（main.c 109–122、176–179 行）

```c
#define TASK_RX_STK      256
#define TASK_CTRL_STK    256
#define TASK_DISP_STK    256
#define PRIO_START  1
#define PRIO_RX     3
#define PRIO_CTRL   2
#define PRIO_DISP   1
...
    RxH   = xTaskCreateStatic(task_rx,   "rx",   TASK_RX_STK,   NULL, PRIO_RX,   RxStack,   &RxTCB);
    CtrlH = xTaskCreateStatic(task_ctrl, "ctrl", TASK_CTRL_STK, NULL, PRIO_CTRL, CtrlStack, &CtrlTCB);
    DispH = xTaskCreateStatic(task_disp, "disp", TASK_DISP_STK, NULL, PRIO_DISP, DispStack, &DispTCB);
    vTaskDelete(StartH);
```

【第 109–112 行】栈大小宏（`START_STK_SIZE=128`、三个任务各 256）。
【第 114 行】`PRIO_START = 1`：启动任务只负责创建，随后自删。
【第 115–117 行】优先级：收包 3 > 控制 2 > 显示 1。
【第 119–122 行】栈与 TCB 都是**全局静态数组**（`RxStack/TASK_RX_STK`、`RxTCB` 等）。
【第 176–178 行】在 `start_task` 里静态创建三个任务。
【第 179 行】`vTaskDelete(StartH)`：创建完把自己删掉。

> [!abstract] 人话翻译
> 数据新鲜度优先：收包最急、控制次之、刷屏最不急。静态创建意味着上电内存布局确定、不产生碎片。

### 3.11 显示任务与 SCREEN_FLIP 的真实实现（main.c 353–391 行，节选）

```c
        OLED_Clear();
#if SCREEN_FLIP
        OLED_ShowChinese(1, 48, "姿态：");

        OLED_ShowString(48, 48, str, 8);
        ...
        OLED_ShowChinese(1, 1, "实际：");

#else
        OLED_ShowChinese(1,  1, "姿态：");
        ...
        OLED_ShowString(48, 48, str, 8);
#endif

```

【第 353 行】`OLED_Clear()`：清显存。
【第 355 行】`#if SCREEN_FLIP`：倒装分支。
【第 356–372 行】倒装时行序是 `48 / 32 / 16 / 1`（姿态→状态→目标→实际 的**反序**）。
【第 373–387 行】`#else`：正装时行序是 `1 / 16 / 32 / 48`。
【第 388 行】`#endif`。
【第 390 行】`OLED_Update()`：整块刷屏。
【第 391 行】`vTaskDelay(pdMS_TO_TICKS(50))`：显示任务 **50 ms** 周期（比控制 20 ms 慢）。

> [!abstract] 人话翻译
> `SCREEN_FLIP` 不是“旋转屏幕”，而是**把四行文字的行坐标倒过来写**（48↔1、32↔16）。所以它只影响显示、不影响控制，改错最多看着别扭。

## 四、硬件与现象对照

| 操作 | 现象 |
|---|---|
| 平放 | 停止 |
| 前倾 12° | 状态“前进”，PWM 被抬到 30% |
| 前倾 45° | 前进，速度约 50 |
| 平放侧翻 30° | 原地转，两轮反向 |
| 前倾 + 侧翻 | 弧线，外轮快内轮慢 |
| 大角度斜推（80/60） | 转弯半径失真（3.5 推导） |
| 捏住一个轮 | 该轮 PWM 顶到 100 |
| 遥控断电 | **车继续跑**（无失联保护） |
| 快速甩腕 | 约 140 ms 后才响应 |

> [!warning] 待确认（防幻觉）
> 轮距、轮径、电机额定转速决定“0~100 对应多少 cm/s”。代码里没有，实物也没量，**不编**。
