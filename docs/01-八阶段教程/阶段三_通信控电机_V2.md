## 📡 本章前置知识点雷达

> [!info] 预习指南：在啃代码之前，先认识这些“硬核名词”
> 本章围绕以下 5 个概念展开。

| 知识点名称 | 一句话通俗解释 | 在本章代码中的角色 |
| :--- | :--- | :--- |
| **任务与优先级** | 多个任务抢一个 CPU，谁急谁先跑。 | `PRIO_RX=3 > PRIO_CTRL=2 > PRIO_DISP=1` |
| **互斥量** | 一组共享数据只允许一个人同时读写。 | `xSemaphoreTake/Give` 保护 `g_pitch/g_roll` |
| **死区** | 输入很小时当 0，防手抖被当指令。 | `DEAD_ZONE=10`、`TURN_THRESHOLD=15` |
| **线性映射** | 角度按比例换算成 0~100 目标速度。 | `speed_x/speed_y` |
| **端到端时延** | 从遥控动作到轮子响应多久。 | 发射 100 + 收包 20 + 控制 20 ms |

## 三、逐行精讲

### 3.1 遥控端 1 ms 时基（遥控 main.c 209–219 行）

```c
void TIM4_IRQHandler(void)
{
	if(TIM_GetITStatus(TIM4,TIM_IT_Update))
	{
		Time_ms++;
		Time_ms2++;
		esp_ms++;
		prekey();
	}
	TIM_ClearITPendingBit(TIM4,TIM_IT_Update);
}
```

【第 209 行】中断函数名必须与向量表一致。
【第 211 行】判断“更新中断”（1 ms 溢出）。
【第 213 行】`Time_ms++`：供主循环判断发送节拍。
【第 214 行】`Time_ms2++`：本工程后续未使用。
【第 215 行】`esp_ms++`：本工程后续未使用。
【第 216 行】`prekey()`：1 kHz 扫按键消抖。
【第 218 行】清中断标志，不清会反复进。
【类型补充】`u16 Time_ms=0, Time_ms2, esp_ms=0;`（遥控 `main.c:52`）。

> [!abstract] 人话翻译
> 中断里只做短事：数时间、扫按键；长活（刷屏、发无线）留给主循环。

### 3.2 10 Hz 发送节拍（遥控 main.c 156–166 行）

```c
	if(Time_ms > 100)
	{
        Time_ms = 0;
        payload.pitch   = pitch;
        payload.roll    = roll;
        payload.gesture = gesture;
        Protocol_Pack(&payload, tx_frame);
        NRF24L01_SendData(tx_frame, 32);
	}
```

【第 156 行】满 100 ms 才发一帧。
【第 158 行】发完归零。
【第 159–160 行】填 pitch、roll。
【第 161 行】填 gesture。
【第 162 行】打包 13 字节有效帧。
【第 165 行】32 字节整包发出。

> [!abstract] 人话翻译
> 主循环每转一圈抬头看“到 100 ms 了吗”，到了就打包、表归零；实际间隔 = 100 ms + 一圈耗时，略大于 10 Hz。

### 3.3 手势映射（遥控 main.c 62–73 行）

```c
static uint8_t Gesture_Map(float pitch, float roll)
{
    const float TH = 15.0f;
    if (pitch >  TH) return GESTURE_FWD;
    if (pitch < -TH) return GESTURE_BACK;
    if (roll  >  TH) return GESTURE_LEFT;
    if (roll  < -TH) return GESTURE_RIGHT;
    return GESTURE_STOP;
}
```

【第 62 行】函数：两个角度 → 0~5。
【第 64 行】阈值 15°。
【第 67 行】pitch 超正阈值 → 前进（先判前后）。
【第 68 行】pitch 超负阈值 → 后退。
【第 69 行】roll 超正阈值 → 左。
【第 70 行】roll 超负阈值 → 右。
【第 72 行】都没超 → 停（5，不是 0）。

> [!abstract] 人话翻译
> 分类器只给方向不给速度；先判 pitch，斜推时左右信息被丢掉。

【第 184 行】`uchar buf[32]`：nRF 定长 32 字节缓冲。

### 3.5 小车端收包后半：限幅 + 加锁写全局（main.c 194–203 行）

```c
                if (pl.pitch >  80.0f) pl.pitch =  80.0f;
                if (pl.pitch < -80.0f) pl.pitch = -80.0f;
                if (pl.roll  >  80.0f) pl.roll  =  80.0f;
                if (pl.roll  < -80.0f) pl.roll  = -80.0f;

                xSemaphoreTake(xMutex, portMAX_DELAY);
                g_pitch   = pl.pitch;
                g_roll    = pl.roll; 
                g_gesture = pl.gesture;
                xSemaphoreGive(xMutex);
```

【第 194–197 行】入口把角度夹 ±80。
【第 199 行】`xSemaphoreTake`：拿“唯一一支笔”。
【第 200 行】写 pitch。
【第 201 行】写 roll。
【第 202 行】写 gesture。
【第 203 行】`xSemaphoreGive` 放笔。

> [!abstract] 人话翻译
> 三个值必须同一次锁写完，否则控制任务可能读到“新 pitch + 旧 roll”。gesture 存进去后全工程**没有任何地方再读它**。

```c
volatile float   g_pitch   = 0;

volatile uint8_t g_gesture = GESTURE_STOP;
volatile uchar   channel;

PID_t pid_left, pid_right;

```

【第 94–96 行】三个 `volatile` 全局：跨任务读写。
【第 97 行】`channel`：**全工程仅此 1 处，死变量**。
【第 100 行】`PID_t pid_left, pid_right;`。
【第 101–102 行】`g_target_*`、`g_act_*`：显示用副本。
【第 103 行】`int16_t g_pwm_disp_L/R`。
【第 105 行】互斥量句柄。
【第 106 行】互斥量静态内存。
【第 114 行】启动任务优先级 1。
【第 115 行】收包 3（最高）。
【第 116 行】控制 2。
【第 117 行】显示 1（最低）。

> [!abstract] 人话翻译
> 数据新鲜度优先：收包最急、控制次之、刷屏最不急。`volatile` 只保证每次去内存读，不保证原子性，所以还要互斥量。

### 3.7 控制任务开头：常量 + 读锁（main.c 213–228 行）

```c
    const float DEAD_ZONE       = 10.0f;  
    const float TURN_THRESHOLD  = 15.0f;  
    const float MAX_SPEED       = 100.0f;  
    const float MIN_SPEED       = 20.0f;   

    while(1)
    {
        xSemaphoreTake(xMutex, portMAX_DELAY);
        pitch   = g_pitch;
        roll    = g_roll;
        xSemaphoreGive(xMutex);
```

【第 217 行】前后死区 10°。
【第 218 行】转向死区 15°。
【第 220 行】速度上限 100。
【第 221 行】`MIN_SPEED=20`：**声明后未使用**（死变量）。
【第 223 行】控制任务主循环。
【第 225 行】拿锁。
【第 226–227 行】拷到局部变量。
【第 228 行】立刻放锁。

> [!abstract] 人话翻译
> 临界区越短越好：只在“读两个数”时持锁，算映射和 PID 都不持锁。

### 3.8 姿态 → 速度（main.c 230–243 行）

```c
        float speed_x = 0.0f; 
        float speed_y = 0.0f; 

        if (pitch > DEAD_ZONE) {
            speed_x = ((pitch - DEAD_ZONE) / (80.0f - DEAD_ZONE)) * MAX_SPEED;
        } else if (pitch < -DEAD_ZONE) {
            speed_x = ((pitch + DEAD_ZONE) / (80.0f - DEAD_ZONE)) * MAX_SPEED;
        }

        if (roll > TURN_THRESHOLD) {
            speed_y = ((roll - TURN_THRESHOLD) / (80.0f - TURN_THRESHOLD)) * MAX_SPEED;
        } else if (roll < -TURN_THRESHOLD) {
            speed_y = ((roll + TURN_THRESHOLD) / (80.0f - TURN_THRESHOLD)) * MAX_SPEED;
        }
```

【第 230–231 行】先清 0。
【第 233 行】超死区才算前进。
【第 234 行】线性映射：45° → 50。
【第 235–236 行】负方向同理。
【第 239 行】roll 超死区才算转向。
【第 240 行】分母 80−15。
【第 241–242 行】负方向同理。

> [!abstract] 人话翻译
> 角度先减死区、再除以“最大角−死区”归一化、最后乘 100；接收端已限 ±80，结果天然不超 100。

### 3.9 差速合成（main.c 245–254 行）

```c
#if REVERSE_TURN
        speed_y = -speed_y; 
#endif

        if (fabs(speed_x) < 0.1f && fabs(speed_y) < 0.1f) {
            targetL = 0; targetR = 0;
        } else {
            targetL = speed_x + speed_y;
            targetR = speed_x - speed_y;
        }
```

【第 245–247 行】`REVERSE_TURN` 为真时转向分量取反。
【第 249 行】两分量都接近 0 → 判停。
【第 250 行】目标清零。
【第 252 行】左轮 = 前进 + 转向。
【第 253 行】右轮 = 前进 − 转向。

> [!abstract] 人话翻译
> 差速就两行：一个加、一个减。x 决定多快、y 决定多急；**没有归一化**，相加可能到 200（阶段八给修法）。

### 3.10 目标 → PID → 起转补偿 → 输出（main.c 256–296 行，节选）

```c
        if (targetL > MAX_SPEED)  targetL = MAX_SPEED;
        if (targetL < -MAX_SPEED) targetL = -MAX_SPEED;
        if (targetR > MAX_SPEED)  targetR = MAX_SPEED;
        if (targetR < -MAX_SPEED) targetR = -MAX_SPEED;
        ...
        pid_left.target  = targetL;
        pid_right.target = targetR;
        pwm_L_temp = PID_Calc(&pid_left,  g_act_left);
        pwm_R_temp = PID_Calc(&pid_right, g_act_right);

        if (targetL > 0.1f) {
            if (pwm_L_temp > 0 && pwm_L_temp < 30) pwm_L_temp = 30;
        } else if (targetL < -0.1f) {
            if (pwm_L_temp < 0 && pwm_L_temp > -30) pwm_L_temp = -30;
        } else {
            pwm_L_temp = 0;
        }
        ...
        Motor_SetPWM(1, (int16_t)pwm_L_temp);
        Motor_SetPWM(2, (int16_t)pwm_R_temp);
```

【第 256–259 行】目标各自夹 ±100。
【第 268–269 行】目标交给 PID——“指令切换目标速度”就在这两行。
【第 271–272 行】PID 算 PWM。
【第 274–275 行】左轮正目标但输出太小 → 抬到 30。
【第 276–277 行】左轮负方向 → −30。
【第 278–280 行】`else`：目标≈0 → 输出 0。
【第 282–288 行】右轮同构（块中 `...` 省略）。
【第 290–293 行】左右再夹 ±100（块中省略）。
【第 295–296 行】写入电机。

> [!warning] 代码块说明
> 块里 `...` 省略了三段：256–259 的后两条、**右轮补偿/清零 282–288**、**再限幅 290–293**；逐字原文见 `main.c:256–296`，不是漏检。

> [!abstract] 人话翻译
> 指令到这里变两件事：目标交给 PID，PID 输出被“起转补偿”抬到至少 30%，最后写进电机；所以目标 5 也按 30 跑——低速不可控的根源。

## 四、硬件与现象对照

| 操作 | 现象 | 依据 |
|---|---|---|
| 前倾 >10° | 两轮同向转 | `:233–237`、`:252–253` |
| 后仰 | 两轮反向转 | 同上 |
| 侧倾 >15° | 两轮一正一反，原地转 | `:239–243`、`:246` |
| 回中 | 目标 0，输出 0 | `:249–250`、`:278–280` |
| 捏住一个轮 | 该轮 PWM 顶到 100 | 闭环 |
| 遥控断电 | **车继续按最后一帧跑** | 无超时保护 |
| 改遥控 `G:` 数字 | 车行为不变 | `g_gesture` 只写不读 |

> [!warning] 时延（算术推导）
> 100 ms（发送间隔）+ 20 ms（收包轮询 `main.c:206`）+ 20 ms（控制 `main.c:303`）≈ **140 ms**。
