## 一、排查总顺序

```text
① 先确认阶段一（串口）与阶段二（单板电机）各自成立
② 再看 g_pitch/g_roll 是否在变（收包链路）
③ 再看 targetL/targetR 是否跟随（映射）
④ 最后看 pwm_L/R 与车轮（输出）
```

> [!info] 三个速查点
> ① 变量不变查无线；② 变量变车不动查目标与补偿；③ 车乱冲查反馈符号。

## 二、【现象】→【可能原因】→【排查步骤】→【修正与防范】

| 现象 | 可能原因 | 排查步骤 | 修正与防范 |
|---|---|---|---|
| 晃遥控，**数字不变** | 无线没通 / 解包失败 / 互斥量死锁 | 调试器看 `buf`、`pl`、`g_pitch`；看是否进 `task_rx` 的 `if` | 先修无线（阶段四）；确认 `Take/Give` 成对 |
| 数字变了，**车不动** | 目标 0 / 补偿被清零 / 电机没供电 | 看 `targetL` 是否 >0.1；量电机电压 | 查死区与目标；供电 |
| 车**一动就猛冲** | 补偿把 0 附近抬到 30；或反馈正反馈 | 看 `pwm_L_temp` 是否直接 30+；给正目标看反馈是否上升 | 改补偿；修反馈符号 |
| 车**一顿一顿** | 周期抖动 / PID 过猛 / 反馈噪声 | 打印周期与 `g_act` | 固定周期、调参、加滤波 |
| **左右反了** | `REVERSE_TURN` / 遥控 `×-1.0f` / `Gesture_Map:66` 三处之一 | 只改一处，逐个试 | 两套开关不要同时动 |
| 遥控断电**继续跑** | 无失联保护 | 关遥控观察 | 记最后收包 tick，超 300 ms 清零 |
| 改遥控 `G:` **车不变** | `g_gesture` 只写不读 | 全局搜索 `g_gesture` | 设计现状，接 `g_gesture` 才有档位 |
| 屏幕卡顿且车抖 | 显示任务抢 CPU | 看优先级 | 显示必须最低（`PRIO_DISP=1`） |

| 工具 | 测什么 | 正常值 |
|---|---|---|
| 调试器 | `g_pitch`、`targetL`、`pwm_L_temp` | 随遥控变化、逐级跟随 |

## 四、本阶段 4 个必踩坑

> [!warning] 坑 1 · 互斥量没成对
> 漏 `Give` 或重复 `Take`（FreeRTOS 互斥量不可递归）→ 任务卡死，表现为“车突然不动、屏幕也停”。

> [!warning] 坑 2 · 死区/阈值三套不一致
> 遥控 15/15、控制 10/15、显示 10/15：`pitch=12°` 会出现“屏幕说停、车却走 30%”。

> [!warning] 坑 3 · 起转补偿的低速陷阱
> 目标 5 也被抬到 30%，调低速跟随永远调不准（`main.c:274–275`）。

> [!warning] 坑 4 · 拿错使能对象
> 改遥控 `Gesture_Map` 只影响显示与协议字节；车由 `DEAD_ZONE/TURN_THRESHOLD` 决定。

---

## 五、10 分钟定位法

1. 调试器看 `g_pitch`：晃遥控是否变化？
2. 不变 → 查阶段四无线与解包。
3. 变 → 看 `targetL/targetR` 是否与倾斜同向。
4. 再看 `pwm_L_temp`：是否 ≥30、是否有正负。
5. 量电机电压与方向脚。
6. 关遥控，看车是否停（判断失联保护）。
