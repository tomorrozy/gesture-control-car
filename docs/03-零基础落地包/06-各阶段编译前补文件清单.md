# 06 各阶段编译前补文件清单（★ 不补就编不过）

> [!danger] 一句话结论
> **八个阶段里，只有「一阶段」和「八阶段」是拿到就能直接 F7 编过的。**
> **二、三、四、五、六、七 阶段的每一个 Keil 工程都缺 2~3 个公共模块**
> （`OLED.c/h`、`OLED_Font.h`、`Key.c/h`、`Delay.c/h`），
> 这些文件**既不在阶段目录里，也没有被加进 Keil 工程** ——
> **不补，F7 的第一条报错就是 `cannot open source input file "OLED.h"`。**
>
> ⚠️ 而 `Keil 公共库\Keil 工程搭建说明.md` 第 102 行写的是
> 「② Build（F7）→ **直接编过**（路径与库都配好了）」——
> **这句话对一阶段/八阶段成立，对二~七阶段不成立。** 请以本文为准。

---

## 一、为什么「完整工程代码」不完整

这个库的设计是**分层复用**：

| 层 | 谁提供 | 说明 |
|---|---|---|
| 启动文件 / CMSIS / 标准外设库 | ★ **`Keil 公共库\Start` + `\Library` + `\User`** | 已配好相对路径，**含 `stm32f10x.h`**，不用管 |
| 本阶段自己写的模块 | 阶段目录 `完整工程代码\` | 命名成「完整工程代码」其实指「**本阶段新写的代码**」 |
| ★ **公共外设模块**（OLED / Key / Delay） | ⚠️ **要你自己从江科大例程里拷** | ★ **这就是缺的那一块** |

所以「完整工程代码」这个名字**容易让人误解**：
它**只是本阶段的产物**，不是「能直接编译的完整工程」。
各阶段 `README_编译前必读` 里其实都写了「**还需要补的文件**」这张表 —— 本文把它汇总并给出**精确复制来源**。

## 三、★ 从哪拷（精确来源，已在库内核实）

所有源文件都在 **`程序源码\程序源码\STM32Project-有注释版\`** 下（推荐用**有注释版**）：

| 要补的文件 | ★ 复制来源（相对本库根） | 备注 |
|---|---|---|
| `OLED.c`、`OLED.h`、`OLED_Font.h` | `程序源码\程序源码\STM32Project-有注释版\4-1 OLED显示屏\Hardware\` | ★ **就用这个**：它用的是 **PB8/PB9 的 4 针软件 I2C**，与本项目完全一致 |
| `Key.c`、`Key.h` | 同上（`4-1 OLED显示屏\Hardware\` **也有** Key）<br>或 `…\3-4 按键控制LED\Hardware\` | 只用它的 `Key_Init()`（配置 PB1/PB11 上拉）；★ `Key_GetNum()` 是**阻塞式**的，本项目不用 |
| `Delay.c`、`Delay.h` | `程序源码\程序源码\STM32Project-有注释版\1-3 Delay函数模块\` | 直接放在根目录，无子文件夹 |

> [!warning] ★★ 别拷错版本：OLED 有两个截然不同的驱动
> | 版本 | 位置 | 引脚 | 能用吗 |
> |---|---|---|---|
> | **4 针 I2C**（★ 用这个） | `1-4 OLED驱动函数模块\4针脚I2C版本\` 或 `4-1 OLED显示屏\Hardware\` | **PB8 / PB9** | ✅ 本项目就用这套 |
> | 7 针 SPI | `1-4 OLED驱动函数模块\7针脚SPI版本\` | PB12/PB13/PB14/PB15 | ❌ **拷了接不上也编不过** |
>
> ★ 判断方法：打开 `OLED.c`，看开头几行 —— 出现 `GPIO_Pin_8 / GPIO_Pin_9` 就是 I2C 版；
> 出现 `PB12~PB15` 就是 SPI 版。

## 四、★ 三步操作（每个需要补文件的工程都要做一遍）

```text
【第 1 步】把文件拷进该工程的源码目录
          一阶段以外的阶段：拷进  0N N阶段\完整工程代码\（就是工程引用的那个目录）
          六/七/八阶段的"两端"工程：各拷各的目录（手带端\ / 小车端\）

【第 2 步】★ 一定要「加进 Keil 工程」，不能只是放在文件夹里
          Keil 里：右键左侧工程名的 Group（如 User / Hardware）
                   → Add Existing Files to Group 'User'...
                   → 文件类型选 All files (*.*)
                   → 选中刚拷进来的 .c 文件（★ .h 不用加，但必须在磁盘上）

          ⚠️ .h 不用加进工程，但要保证它在：
             ① 与 .c 同目录（ARMCC 会先找"当前文件所在目录"）
             ② 或者被 IncludePath 覆盖

【第 3 步】F7 编译 → 应看到 0 Error
          若还报「找不到 xxx.h」→ 检查它是不是真在源码目录里、或 IncludePath 是否漏了该目录
```

> ★ **双端工程（三/四/六/七阶段）两端都要各补一遍** ——
> 只补一端会出现「一端编过、另一端报错」。

## 五、报错对照表（补文件过程中会遇到的全部错误）

| # | Keil 报错 | 原因 | 处理 |
|:--:|---|---|---|
| 1 | `cannot open source input file "OLED.h"` | 没拷 OLED 驱动 | 照第三节拷 `4-1 OLED显示屏\Hardware\` 下的 3 个文件 |
| 2 | `cannot open source input file "Key.h"` | 没拷 Key 模块 | 拷 `Key.c / Key.h`（同上目录） |
| 3 | `cannot open source input file "Delay.h"` | 没拷 Delay 模块 | 拷 `1-3 Delay函数模块\Delay.c / Delay.h` |
| 4 | `undefined symbol OLED_Init` / `OLED_ShowString` | ★ **文件拷了但没加进工程** | 做第 2 步「Add Existing Files to Group」 |
| 5 | `undefined symbol Key_Init` / `Delay_ms` | 同上（Key.c / Delay.c 没加） | 同上 |
| 6 | `Symbol xxx multiply defined` | 把 `stm32f10x_it.c` 也编进去了 | 从工程移除它 |
| 7 | `cannot open source input file "stm32f10x.h"` | IncludePath 失效（库被单独挪动） | 整个库一起搬；或补 3 条 `Keil 公共库` 相对路径 |
| 8 | 拷了 SPI 版 OLED 后编译过、**屏幕全黑** | 拷错版本（PB12~PB15） | 换成 4 针 I2C 版（见第三节警告） |
| 9 | 编译过、下载后**屏幕花屏/重叠** | 列预算算错（OLED 按列覆盖） | 见各阶段 README 的「列预算」章节 |
| 10 | 编译过、下载后**屏幕亮但没内容** | I2C 接线/上拉/供电 | 查 PB8/PB9、3.3V、GND |
