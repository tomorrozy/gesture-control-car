# 05 引脚权威总表与阶段接线改动

## 三、★★ 阶段 7 → 阶段 8 必须做的「3 改 + 3 增」

> [!danger] 这是整套材料里**最容易漏、后果最明显**的一步
> 阶段 8 为了「两路 PWM + 两个编码器接口」，把引脚重排了一遍。
> **如果你沿用阶段 7 的接线直接烧阶段 8 的固件，一定出问题**，但报错现象会误导你。

| # | 动作 | 不改的后果 | 出处 |
|:--:|---|---|---|
| **改 1** | ★★ **拔掉 PA3 → TB6612 的 STBY 线，把 STBY 改接 3.3V** | 右轮**抽搐、时转时停**（PWM 在不停开关整片使能） | `八阶段 MOC` L188、`README_编译前必读 八阶段` L119 |
| **改 2** | ★★ **把 MPU6050 的 SCL/SDA 从 PB6/PB7 挪到 PB8/PB9**（与 OLED 并接） | **姿态读数全 0 或乱跳**，看 OLED 正常但车不动 | `八阶段 完整代码汇编` L462、`README_编译前必读 八阶段` L454 |
| **改 3** | ★ **MPU6050 的 AD0 必须接 GND**（地址 0x68） | 地址错 → 读不到 | `接线总图与总表` L87 |
| **增 1** | ★ **PB3 → 右电机 BIN1、PB4 → 右电机 BIN2** | 右轮完全不转 | `Board.h` L22-23 |
| **增 2** | ★ **PB6/PB7 → 右编码器 A/B 相** | 右轮没有反馈 → PID 失控 | `Board.h` L25 / L61-62 |
| **增 3** | ★ **PA3 → 右电机 PWMB（TIM2_CH4）** | 右轮没有调速能力 | `Board.h` L19 / L46 |

另加：**TB6612 的 AO1/AO2 → 左电机，BO1/BO2 → 右电机**。

> ★ 阶段 8 的 `Board.h` L37-38 已经把这两条写成警告：
> 「PB3/PB4 复位后是 JTAG 的 JTDO/NJTRST，不禁用 JTAG 则配了也没波形」
> 「若已按七阶段把 PA3 接到 TB6612 的 STBY，必须拆掉改接 3.3V」。

## 四、★ 文档冲突清单（已核实，**结论：以代码/阶段 README 为准**）

### 冲突 1（★ 最要命）：阶段 5~7 的 MPU6050 到底在 PB6/PB7 还是 PB8/PB9

| 说法 | 出处 | 内容 |
|---|---|---|
| **A. 代码 = PB6/PB7** | `五阶段\完整工程代码\MyI2C.h` L19-20；`六阶段\完整工程代码\手带端\MyI2C.h` L19-20；`七阶段\完整工程代码\手带端\MyI2C.h` L19-20；`五阶段\完整工程代码\README_编译前必读 五阶段.md` L42-43、L56、L103 | 「SCL→**PB6**、SDA→**PB7**（★ 不是例程的 PB10/PB11）」 |
| **B. 接线图 = PB8/PB9** | `接线\接线图索引.md` L27；`接线总图\各阶段接线变化说明.md` L132；`接线总图\接线总图与总表.md` L81-82；`接线\接线全过程 总图与分步.md` L104；`接线总图\面包板接线图\面包板接线图.md` L35 | 「五阶段 新增 **PB8/PB9** → MPU6050（与 OLED 共用）」 |

> [!warning] 结论
> **接线类文档画的是「最终（阶段 8）形态」的引脚，被套用到了阶段 5/6/7 上。**
> ★ **做阶段 5、6、7 时，MPU6050 接 PB6/PB7**（否则代码读不到，`WHO_AM_I` = 0x00）；
> ★ **做阶段 8 时，必须挪到 PB8/PB9**。
> 这处冲突会直接让零基础的人在阶段 5 卡住一整天，**必须修**（修法见 [[补充建议 零基础落地缺口清单]]）。

### 冲突 2：TB6612 的 VCC 接 5V 还是 3.3V

| 说法 | 出处 |
|---|---|
| **接 5V** | `二阶段\任务1\阶段二 任务1 PWM开环调速与正反转.md` L45/L48；`七阶段\完整工程代码\README_编译前必读 七阶段.md` L44；`六阶段\...README` L69 |
| **接 3.3V** | `接线总图\接线总图与总表.md` L70；`接线\接线全过程 总图与分步.md` L153 |

> ★ **结论**：为与 STM32 的 3.3V 电平匹配，**建议 VCC 接 3.3V**；
> 已接 5V 且功能正常的可以不改，但要**记进实测记录**（详见 [[03 供电共地与上电安全]] 第五节）。

### 冲突 3（轻微）：阶段 8 的定时器号写法

| 说法 | 出处 | 说明 |
|---|---|---|
| 控制周期用 **TIM1** | `八阶段\完整工程代码\README_编译前必读 八阶段.md` §3.1 | ★ 八阶段的正确做法 |
| 「由 **TIM4** 中断调用」 | `二阶段\完整工程代码\Encoder.h` L29、`七阶段\...Encoder.h` L29 | 那是二/七阶段的注释；★ 二/七阶段确实用 TIM4 做控制周期，**八阶段改成 TIM1**（TIM4 被右编码器占了） |

## 五、外设 / 定时器分配总表（阶段 8）

| 外设 | 用途 | 引脚 | 说明 |
|---|---|---|---|
| **TIM1** | 控制周期中断（10ms） | — | ★ 八阶段改用它（不是 SysTick、也不是 TIM4） |
| **TIM2** | 双路 PWM（20kHz） | PA2 (CH3) / PA3 (CH4) | ARR=99、PSC=35 |
| **TIM3** | 左编码器接口 | PA6 / PA7 | 硬件编码器模式 |
| **TIM4** | 右编码器接口 | PB6 / PB7 | ★ 八阶段新增 |
| **USART1** | 蓝牙（+ DMA） | PA9 / PA10 | 9600,8,N,1（两端一致） |
| **软件 I2C** | OLED (+MPU6050) | PB8 / PB9 | ★ 必须**全在主循环**，不能放中断 |
| **GPIO** | 方向 / 按键 / LED / STBY | PA4 PA5 PB3 PB4 / PB1 PB11 / PA1 PA0 / 3.3V | — |
| **调试** | SWD | PA13 / PA14 | 禁 JTAG 时**保留 SWD** |

> ★ **为什么八阶段必须重排引脚**：C8T6 只有 3 个通用定时器 + 1 个高级定时器，
> 而「编码器接口」必须**独占整个定时器的 CH1/CH2**，两路编码器就吃掉了 TIM3 和 TIM4。
> 推导过程见 `八阶段\引脚规划与改动说明.md`。

## 六、接线自查 10 条（★ 每次改完线都过一遍）

| # | 检查 | 为什么 |
|:--:|---|---|
| 1 | ★★ **TX 与 RX 交叉**（TX→RX，RX→TX） | 不交叉 = 两张嘴对喊，永远收不到 |
| 2 | ★★ **共地**：所有模块 GND 连到一起 | 不共地 = 乱码/读不到 |
| 3 | ★★ **电机两轮悬空**再上电 | 防冲出去 |
| 4 | ★ **STBY 电压 = 3.3V**（万用表量） | 不为高 → 电机完全不转且不报错 |
| 5 | ★ **TB6612 的 VM 有 12V、VCC 有 3.3V/5V** | 缺 VM 芯片不工作 |
| 6 | ★ **PA3 上到底接的是 STBY 还是 PWMB** | 阶段 8 混淆就会出现「右轮抽搐」 |
| 7 | ★ **MPU6050 接的是 PB6/PB7 还是 PB8/PB9** | 阶段 5~7 与阶段 8 **不一样** |
| 8 | ★ **MPU6050 的 AD0 是否接 GND** | 决定地址 0x68 / 0x69 |
| 9 | ★ **OLED 的 SCL/SDA 有没有接反** | 全黑屏 |
| 10 | ★ **电源正负极是否接反、杜邦线是否插到底** | 反接 = 烧板 |
